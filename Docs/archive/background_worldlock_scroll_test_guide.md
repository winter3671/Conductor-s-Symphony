# 배경 월드 고정 스크롤 버그 수정 - 검증 가이드

이 문서는 **Unity MCP가 연결된 별도 Claude Code 세션**에서 이번 작업을 실측 검증할 때 참고하는
절차서입니다. 아직 커밋하지 않은 상태입니다.

검증이 끝나면 이 파일 하단(4절)에 결과를 추가로 append하고, `archive/`로 옮겨주세요.

## 0. 무엇을 고쳤나

`archive/background_tiling_test_guide.md`(무한 타일링 배경, PASS 완료) 이후 사용자가 직접
플레이해보고 발견한 문제: **배경이 캐릭터를 따라다니는 스티커처럼 보임 - 방향키로 이동해도 이동감이
전혀 없었음.**

- **원인**: 기존 `BackgroundTiler.LateUpdate()`는 배경 오브젝트의 `transform.position`을 매 프레임
  카메라 위치와 완전히 동일하게 맞추기만 했다. 오브젝트가 카메라와 항상 같은 양만큼 같이 움직이므로
  화면 기준 상대 위치가 항상 0으로 고정 - 즉 카메라가 아무리 움직여도 화면에 보이는 무늬 자체는
  절대 안 바뀌는 구조였다. 이전 테스트(4-4절)는 `bg.position == cam.position`(오브젝트가 카메라를
  잘 따라가는지)만 확인했을 뿐, "카메라가 움직이면 무늬가 실제로 스크롤되는지"는 검증 범위에 없어서
  놓쳤다.
- **수정**: `Assets/Scripts/Environment/BackgroundTiler.cs`에 재질 텍스처 오프셋 스크롤을 추가.
  `Awake()`에서 `spriteRenderer.material`(자동으로 인스턴스 머티리얼 생성)과
  `tileWorldSize`(스프라이트 픽셀 크기 ÷ `pixelsPerUnit`, 즉 텍스처 한 칸이 차지하는 월드 유닛)를
  캐싱. `LateUpdate()`에서 덮개(Tiled 메시)는 기존처럼 카메라를 따라가되(화면을 항상 덮기 위함),
  `materialInstance.mainTextureOffset = (camPos.x / tileWorldSize, camPos.y / tileWorldSize)`로
  텍스처 오프셋을 카메라의 월드 좌표에 비례해서 스크롤한다. 텍스처 Wrap Mode가 Repeat이라 오프셋이
  순환하며 이어지므로, 무늬가 "월드에 고정된 무한 격자"처럼 보이고 카메라(플레이어)가 그 위를
  실제로 지나가는 것처럼 보이게 된다.
- 판정/스폰/밸런스 등 다른 로직은 전혀 건드리지 않았다.

이펙트 등 흰색 UI 요소가 잘 안 보임. 기존 게임 배경색(카메라 `m_BackGroundColor` = RGB
`(0.192, 0.302, 0.475)`, 약 `#314D79` 남색)과 어울리는 톤으로 나노바나나에 새 이미지를 다시
요청하기로 함(대화 기록 참고). **완료(2026-08-09)**: 사용자가 남색 헤링본 마룻바닥 패턴을 새로
생성해서 전달, `ParquetFloor.png`를 교체함. 타일 이음매 확인을 위해 2x2 모자이크를 만들어 좌우/
상하 경계를 직접 눈으로 대조해봤는데(파이썬 PIL로 합성) 두 방향 다 이음매가 전혀 안 보이고
패턴이 자연스럽게 이어짐 - 시각적으로 완전히 seamless. 새 파일에 대해 Unity가 기본 임포트 설정
(Sprite Mode = Multiple, Wrap = Clamp, Mesh Type = Tight)으로 새 `.meta`를 만들어놨길래, 이전
세션에서 검증됐던 설정(Sprite Mode = Single, Wrap = Repeat, Mesh Type = Full Rect)으로 직접
맞춰 고쳐뒀음 - Unity 에디터에서 실제로 다시 인식되는지는 아직 미확인(다음 Unity MCP 세션에서
`refresh_unity` 후 재확인 필요, 2절 체크리스트에 추가).
색상/대비(남색 톤이 흰색 UI 요소와 잘 구분되는지)는 실제 게임 화면에서 Unity MCP 세션이
스크린샷으로 육안 재확인 필요.

## 4. 검증 결과

**검증일: 2026-08-09 / 검증 환경: Unity MCP (Unity 6000.5.5f1, 씬 Assets/Scenes/Gameplay.unity)**

### 4-0. ⚠️ 차단 이슈 발견: `ParquetFloor.png`가 손상된 상태(빈 파일) - 사용자 확인 필요

검증을 시작하자마자(Play 모드에서 `SpriteRenderer.sprite`가 계속 `NULL`로 나옴) 조사한 결과,
**`Assets/Resources/Sprites/Background/ParquetFloor.png`가 4,100,045바이트 전체가 처음부터 끝까지
전부 0x00(널 바이트)인 빈 파일**임을 확인했습니다(`cmp -l file /dev/zero`로 전체 바이트 대조,
차이 0건 - PNG 헤더(`89 50 4E 47...`)조차 없음). Unity 콘솔에도 재임포트 시도 시
`"Could not create asset from ...ParquetFloor.png: File could not be read"` 에러가 찍힘. OneDrive
placeholder(미동기화 자리표시자) 여부도 `fsutil reparsepoint query`로 확인했으나 아니었고, 일반
로컬 파일인데 내용만 비어있는 상태였습니다.

작업 도중 이 문서의 3절 내용이 실시간으로 갱신된 것을 발견했는데(사용자가 남색 헤링본 패턴을
새로 생성해 `ParquetFloor.png`를 교체하고 `.meta`도 수동으로 고쳐뒀다는 내용), 타이밍상 **이미지
"파일 자체(픽셀 데이터)"를 옮기는 과정만 실패하고 `.meta` 설정 수정은 반영된 상태**로 보입니다.
`.meta`는 정상입니다(Sprite Mode=Single, Wrap=Repeat, Mesh Type=Full Rect 전부 사용자가 고친 그대로
확인됨) - 문제는 순수하게 PNG 바이너리 내용이 비어있다는 것뿐입니다.

**요청사항**: 새로 생성하신 남색 헤링본 이미지 파일을 `ParquetFloor.png` 자리에 다시 저장/복사해
주세요(내용이 실제로 들어갔는지 파일 크기 등으로 한번 확인 부탁드립니다). 재전달해주시면 바로
이어서 재임포트 확인 + 색상/가독성 육안 확인 + 실제 아트로 이동감 재확인을 진행하겠습니다. 이
이미지 파일은 제가 만들 수 있는 게 아니라 직접 손대지 않고 그대로 뒀습니다.

### 4-1. 컴파일 에러/경고: 0건 ✅

`refresh_unity(force, compile=request)` 후 확인 - 에러/경고 0건(코드 자체는 문제 없음).

### 4-2. 스크롤 공식 검증 (합성 텍스처 사용, 실제 아트는 4-0절 사유로 대체 불가) ✅

`ParquetFloor.png`가 못 쓰는 상태라, 프로젝트 에셋을 전혀 건드리지 않고 **런타임에만 존재하는
임시 64×64 텍스처/스프라이트**(디스크에 저장 안 함, `Sprite.Create()`로 메모리에서만 생성,
pixelsPerUnit=100)를 별도 임시 GameObject에 붙여 `BackgroundTiler`의 로직만 격리 검증:

- `tileWorldSize` 계산: `64px / 100ppu = 0.64` → 실측값 `0.64` 일치.
- 카메라를 (3.2, 1.6)으로 이동 → `mainTextureOffset` 실측 `(5.00, 2.50)` = `(3.2/0.64, 1.6/0.64)`
  공식과 정확히 일치. **즉 카메라가 움직이면 텍스처 오프셋도 같이 움직인다 - "스티커처럼 고정"되던
  기존 버그가 코드 레벨에서 확실히 고쳐졌음.**
- 카메라를 원래 위치로 되돌림 → 오프셋도 정확히 `(0.00, 0.00)`으로 복귀(왕복 일관성 확인).

테스트에 쓴 임시 오브젝트/텍스처는 즉시 `Destroy()`로 정리해 프로젝트에 아무 흔적도 남기지
않았습니다.

### 4-3. 화면 커버리지 회귀 없음 ✅

실제 `Background` 오브젝트(sprite가 null인 상태 그대로)로 재확인 - `LateUpdate()`의 위치 추적/크기
재계산 부분은 sprite 참조와 무관하게 독립적으로 동작함을 코드 구조로 확인(오프셋 계산만
`sprite != null` 가드 안에 있고, 위치/크기 로직은 그 위에 있음). 플레이어를 (77, -33)으로 옮긴 뒤
카메라/배경 모두 정확히 그 위치로 동기화됨(`bgPos == camPos`), `size=(24.89, 14.00)`도 이전 세션과
동일하게 정상 산출. `drawMode=Tiled`, `sortingOrder=-100` 유지 확인.

### 4-4. 성능 - 코드 검토 ✅

`spriteRenderer.material` 접근으로 생성되는 인스턴스 머티리얼은 이 배경 오브젝트 하나에서만
캐싱되어(`Awake()`에서 1회) 매 프레임 재생성되지 않으므로 GC/드로우콜 영향 없음. 씬에 배경
오브젝트가 1개뿐이라 배치(batching)에도 영향 없음 - 별도 실측 불필요로 판단.

### 4-5. 재검증: 사용자가 이미지 재저장 후 재임포트 확인 ✅

사용자가 `ParquetFloor.png`를 다시 저장한 뒤 재확인. 이번엔 PNG 헤더(`89 50 4E 47...`)가 정상이고
`cmp`로 전체 바이트 대조해도 더 이상 전부 0이 아님(실제 픽셀 데이터 존재, 1710×1710). 다만 파일을
다시 저장하는 과정에서 **`.meta`가 Unity 기본값(Sprite Mode=Multiple, Wrap=Clamp, Mesh
Type=Tight)으로 재생성**되어 있었음(4-0절에서 확인했던 "사용자가 수동으로 고친 설정"은 이번
재저장 때 유실된 것으로 보임) - `TextureImporter` API로 동일하게 Single/Repeat/Full Rect 재적용
후 재임포트, 정상 로드 확인(`loadedSprite=ParquetFloor`, `rect`가 텍스처 전체 100% 커버).
Play 모드 재진입 시 콘솔 에러/경고 0건("Full Rect" 경고도 더 이상 안 뜸).

### 4-6. 재검증: 실제 아트로 이동감 + 색상 육안 확인 ✅

Play 모드 스크린샷 3장으로 확인:
1. 플레이어 원점 - 남색 헤링본 무늬가 화면을 채움. 흰색 판정 링, SCORE/COMBO/HP 텍스트 등 UI
   요소가 배경과 뚜렷하게 대비되어 잘 보임(기존 흰색 배경 대비 가독성 문제 해결 확인).
2. 플레이어를 x=8(타일 크기 17.1의 절반 정도)만큼 이동 - `mainTextureOffset`이 `(0.47, 0.00)`으로
   계산됨(`8/17.1`과 일치). 스크린샷에서 플레이어는 화면 중앙에 그대로 고정돼 있지만, 무늬의
   헤링본 이음선 위치가 1번 스크린샷과 눈에 띄게 달라짐 - **"캐릭터가 제자리서 걷는 것처럼 보이던"
   기존 버그가 실제 아트로도 확실히 고쳐졌음을 육안으로 확인.**
3. 원점으로 복귀 - `mainTextureOffset`이 정확히 `(0.00, 0.00)`으로 돌아오고, 스크린샷도 1번과
   픽셀 단위로 동일한 무늬 위치로 복귀함(왕복 일관성, 실제 아트 기준 재확인).

### 4-7. 재검증: 화면 비율/커버리지 회귀 없음(실제 텍스처) ✅

`orthographicSize`를 5→10→5로 바꿔가며 재확인 - `size`가 매번 `(orthoSize*2+margin, 그 값*aspect)`
공식대로 정확히 재계산됨(이전 세션의 합성/null-sprite 테스트와 동일한 결과, 실제 텍스처로도 동일하게
작동).
