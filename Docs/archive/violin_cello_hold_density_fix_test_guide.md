# 바이올린/첼로 홀드 과밀 동일 버그 점검 및 수정 - 검증 가이드

이 문서는 **Unity MCP가 연결된 별도 Claude Code 세션**에서 이번 작업을 실측 검증할 때 참고하는
절차서입니다. 아직 커밋하지 않은 상태입니다.

검증이 끝나면 이 파일 하단에 결과를 추가로 append해주세요.

## 0. 무엇을 고쳤나

팀파니 홀드 과밀 버그(`bugfix_burst_scale_and_boss_targeting_test_guide.md` 0-3절) 수정 후, 사용자가
"같은 현상이 바이올린 등 다른 홀드 악기에도 있는 것 같다"고 요청해 홀드 4종(바이올린/프렌치호른/첼로/
플루트) 전체를 시뮬레이션으로 재점검했습니다(`RhythmManager.ProcessSequencerStep`의 겹침 방지 로직을
Python으로 그대로 재현 - 32스텝 사이클 8회 반복 후 정상상태 측정).

**바이올린/첼로 — 팀파니와 동일한 버그 확인, 수정함.** 홀드 길이(기존 13스텝)가 Lv1~3 패턴의 온셋
간격(8~16스텝)보다 넓어서, 레벨과 무관하게 항상 정확히 2회/32스텝 사이클(휴식 단 3스텝)로 고정되어
있었습니다 - Lv4~5가 패턴에 추가한 온셋들은 전부 겹쳐서 조용히 스킵되어 레벨업 밀도 상승이 작동하지
않았습니다(팀파니와 완전히 같은 원인). `holdLengthSteps`를 13→11로 줄였습니다:
- Lv1~3: 여전히 2회/사이클이지만 휴식이 3→5스텝으로 늘어남.
- Lv4~5: 온셋 간격(4스텝)이 새 홀드 길이(11)보다 좁아지면서, 사이클마다 위상이 자연스럽게 밀려
  평균 2.7회/사이클(휴식 1스텝)까지 실제로 늘어남 - "레벨이 오를수록 더 바빠진다"가 처음으로 의미
  있게 작동합니다.

**프렌치호른/플루트 — 시뮬레이션 결과 버그 아님, 그대로 둠.** 두 악기는 온셋 간격이 홀드 길이보다
좁아서(프렌치호른 6, 플루트 3), 오히려 레벨이 오를수록 실제 발동 횟수도 늘어나고 있었습니다
(프렌치호른 2→4회/사이클, 플루트 2→4→6→8회/사이클) - 팀파니/바이올린/첼로처럼 "레벨업 온셋이
낭비되는" 문제가 아니라 설계 의도대로 "레벨이 오를수록 바빠지는" 게 실제로 작동 중인 상태입니다.
다만 최고 레벨에서 휴식이 1스텝까지 좁아지긴 하지만(프렌치호른 Lv5, 플루트 Lv3+), 애초에 이 두
악기는 "짧고 잦은 홀드"가 컨셉이라 팀파니/바이올린/첼로만큼 심각하게 느껴지지 않을 것으로 판단해
건드리지 않았습니다. 플레이해보고 이 둘도 너무 빡빡하게 느껴지면 알려주세요.

## 1. 사전 준비

1. `refresh_unity(mode=force, compile=request)` → `read_console`로 컴파일 에러 확인.
2. `RhythmManager`의 시뮬레이션(패턴+겹침 방지 로직)을 코드로 직접 재현하거나, 실제 플레이로 여러
   사이클 동안 홀드 시작/종료 타이밍을 관찰하는 방식 둘 다 가능합니다(팀파니 검증 때와 동일 방법).

## 2. 검증 항목

- [ ] `GetHoldLengthSteps(Violin)` = 11, `GetHoldLengthSteps(Cello)` = 11 확인
- [ ] 바이올린/첼로 Lv1~3: 32스텝 사이클마다 홀드가 2회 발동하고 각 홀드 사이 실제 휴식이 약 5스텝인지
- [ ] 바이올린/첼로 Lv4~5: 사이클당 발동 횟수가 Lv1~3보다 늘어나는지(평균 약 2.7회/사이클, 정확히
      정수로 안 떨어지고 사이클마다 위상이 조금씩 밀리는 것도 정상 동작임)
- [ ] 프렌치호른/플루트: `holdLengthSteps`가 이번 변경으로 바뀌지 않았는지(회귀 확인, 각각 6/3)
- [ ] **회귀**: 바이올린/첼로의 홀드 중 실제 이펙트(칼날 회전/참격, 중력장 감속·피해)는 이번 변경과
      무관하게 그대로인지 - `holdLengthSteps`만 바뀌었을 뿐 각 이펙트의 `Init`/`OnHoldTick` 로직은
      손대지 않았음
- [ ] **회귀**: 팀파니(10)/글록켄슈필 관련 값들은 이번 변경과 무관하게 그대로인지

**결론**: 바이올린/첼로가 팀파니와 동일한 "홀드 길이가 온셋 간격보다 넓어 레벨업 밀도 상승이 무의미해지는"
버그를 갖고 있었다는 진단이 정확했고, `holdLengthSteps` 13→11 축소로 Lv1~3은 휴식이 3→5스텝으로
여유로워지고 Lv4~5는 평균 2.7회/사이클까지 실제로 밀도가 올라가 "레벨이 오를수록 바빠진다"가 의도대로
작동함을 시뮬레이션으로 확인. 프렌치호른/플루트를 건드리지 않기로 한 판단도 해당 두 악기의
`holdLengthSteps`가 그대로임을 재확인해 뒷받침됨. 두 악기의 실제 전투 로직(회전 칼날/중력장)에는
회귀가 없고, 팀파니/글록켄슈필 등 다른 악기 값도 영향받지 않음. 코드 변경 불필요, 추가 조치 없음.
테스트 중 생성한 임시 GameObject는 모두 정리함.
