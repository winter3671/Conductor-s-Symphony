# 프렌치호른 부채꼴 / 잔류 장판 / 바이올린 칼날 정지 이미지 연동 - 검증 가이드

이 문서는 **Unity MCP가 연결된 별도 Claude Code 세션**에서 이번 작업을 실측 검증할 때 참고하는
절차서입니다. 아직 커밋하지 않은 상태입니다. 사용자가 첼로/플루트와 묶어서 한 번에 배치 테스트하기로
했으니, 그 세션에서 아래 항목도 같이 진행해주시면 됩니다.

검증이 끝나면 이 파일 하단(4절)에 결과를 추가로 append해주세요.

## 0. 무엇을 고쳤나

세 가지 정지 이미지를 각각 연동했습니다(영상 토큰 소진으로 전부 정지 이미지 1장만 사용, 사용자 결정).

### 1) 프렌치호른 부채꼴 (`FrenchHornConeEffect.cs`)

`Assets/Resources/Sprites/Effects/HornCone/HornCone.png`(뾰족한 끝=플레이어 위치, 넓은 쪽=뻗어나가는
방향의 실제 부채꼴 모양, 브라스 골드 톤 직접 채색).

- **가장 큰 변화**: 기존엔 원으로 근사 표시하면서 회전 없이 "부모 위치를 range*0.4만큼 앞으로 미리
  밀어두는" 트릭으로 방향성을 흉내냈습니다. 진짜 방향성 있는 부채꼴 아트로 바뀌면서 이 트릭이 더 이상
  맞지 않아 제거하고, `OnHoldTick`에서 매 프레임 `facing` 방향으로 실제 `transform.rotation`을
  적용하도록 바꿨습니다.
- **피벗 보정**: 아트의 콘텐츠 폭(끝~밑변)이 정확히 `range`가 되도록 `ApplyConeArt()`에서 균등
  스케일하고, 아트의 "뾰족한 끝"이 오브젝트 로컬 원점(플레이어 위치)에 오도록 `sprite.bounds.min.x`
  기준으로 위치를 보정했습니다(임포트 피벗 설정에 의존하지 않음).
- **폴백**: 에셋 로딩 실패 시 기존 원+포워드오프셋 방식을 100% 그대로 유지(회귀 없음) - `usingRealArt`
  플래그로 두 경로를 분기.
- 범위 링(사거리 정확 표시)은 기존처럼 계속 표시(부채꼴이라 실제 판정은 일부지만 최대 사거리 정보는
  여전히 유효).

### 2) 잔류 장판 (`LingeringZoneEffect.cs`) - 팀파니Lv5/벨Lv5/바이올린Lv5 공유

`Assets/Resources/Sprites/Effects/LingeringZone/LingeringZone.png`(무채색 회색조 룬 서클, 중심에서
균열이 퍼지는 모양).

- 세 악기가 서로 다른 `color`를 넘기며 이 클래스 하나를 공유하는데, 기존엔 색을 텍스처에 직접
  구워 넣는 방식이라 대응이 안 됐습니다. 무채색 아트 + `SpriteRenderer.color` 런타임 틴트(빔/버스트와
  동일 패턴)로 바꿔서 세 악기 색 전부 정확히 반영되도록 했습니다.
- 콘텐츠 크기 정규화(`ReferenceContentSize=0.2`, 기존 `CreateFilledCircle(20,9f,...)` 기준)로 이중
  확대 사전 방지, 폴백 시 기존과 수학적으로 동일한 크기.

### 3) 바이올린 칼날 (`ViolinOrbitEffect.cs`)

`Assets/Resources/Sprites/Effects/Blade/Blade.png`(무채색 4방향 별/블레이드 모양).

- 기존에도 무채색 + `sr.color = color` 런타임 틴트 방식이라 틴트 로직 자체는 그대로 - 콘텐츠 크기
  정규화만 추가(`BladeReferenceContentSize=0.16`, 기존 `CreateDiamond(16,7f,...)` 기준). 정규화 없이
  그대로 붙였으면 원본 대비 100배 넘게 이중 확대됐을 콘텐츠 크기 차이였습니다(16x16px → 약
  1682x1718px).
- 릴리즈 참격(`slashSprite`)은 이미 빔 아트로 별도 처리 중이라 이번 변경과 무관.

## 1. 사전 준비

1. `HornCone/HornCone.png`, `LingeringZone/LingeringZone.png`, `Blade/Blade.png`에 아직 `.meta`가
   없다면 `refresh_unity(mode=force, compile=request)`로 최초 임포트.
2. 각 폴더에 `.png~` 백업 파일이 남아있는데(`LingeringZone.png~`, `Blade.png~`), 확장자가 `.png`가
   아니라 Unity가 임포트하지 않습니다 - 무시해도 되지만 정리하고 싶으면 지워도 됩니다.
3. `refresh_unity(force, compile=request)`로 재적용 후 컴파일 에러/경고 0건 확인.

## 4. 검증 결과

**검증 일시**: 2026-08-08, Unity MCP 연결 세션(`My project@c018c67b9a01a4e5`, Unity 6000.5.5f1) - 첼로/
플루트와 함께 배치 테스트로 진행.

**1절 사전 준비**: `refresh_unity(force, compile=request)`로 최초 임포트, `.meta` 자동 생성(`.png~`
백업 파일은 예상대로 임포트 안 됨), 컴파일 에러/경고 0건.

### 프렌치호른

- [x] **회전 추종**: `OnHoldTick()` 호출 시 `transform.position`이 플레이어 위치에 고정되고
      `transform.rotation`이 `facing` 방향(`Atan2`)과 정확히 일치(기본 아래 방향 → z=270°=-90°)함을
      확인.
- [x] **뾰족한 끝 고정**: `ApplyConeArt()`에서 `sprite.bounds.min.x`(=-0.06) 기준으로
      `fieldArtTransform.localPosition.x = -min.x×scale`을 계산 - 실측 결과 아트 좌표계에서 콘텐츠의
      가장 왼쪽 끝(뾰족한 끝)이 정확히 부모(플레이어) 로컬 원점(0,0)에 오도록 보정됨을 좌표 계산으로
      확인(로컬 포지션 1.5, 스케일 25일 때 -(-0.06)×25=1.5, 아트 로컬 좌표 -0.06이 최종적으로
      1.5+(-0.06×25)=0에 정확히 맞음). 회전은 부모 트랜스폼이 담당하므로 자식은 회전에 자동으로
      딸려와 흔들리지 않음.
- [x] **크기 검증**: `fieldArtTransform.localScale.x × sprite.bounds.size.x`가 Lv1(range=3.0)에서
      3.000000, Lv2(range=3.75=3.0×1.25)에서 3.750000으로 `range`와 정확히 일치.
- [x] **폴백 회귀**: `coneSprite`를 임시로 null 처리(로드 실패 시뮬레이션) 후 재초기화 →
      `usingRealArt=False`, 기존 원+포워드오프셋 공식(`localScale=range×0.8×0.24/0.24=range×0.8`,
      위치=`player+facing×range×0.4`)과 정확히 일치하는 결과 확인. 이후 원래 상태로 복원.
- [x] **회귀 - 판정/넉백/Lv4/보스**: 부채꼴 안(거리+각도 조건 만족)의 적만 피해를 받고 범위 밖/각도
      밖/사거리 밖 적은 변화 없음을 확인(허수아비 3종 배치 테스트). 넉백
      (`knockbackSpeed×TickInterval`)도 계산값과 정확히 일치하는 만큼 밀려남. Lv4 피해증폭
      디버프(×1.15)가 적용된 상태로 데미지가 실제로 증폭되어 들어감(12 피해 요청 시 실제 14 피해,
      `RoundToInt(12×1.15)`와 일치)을 확인, 부채꼴을 벗어나면 디버프가 정확히 해제(1.0 복원)됨을
      확인. 보스는 디버프 없이 순수 피해(12)만 정확히 들어감(기존 관례 유지, 회귀 없음).

### 잔류 장판

- [x] **악기별 색 틴트**: 팀파니(갈색)/벨(청록)/바이올린(보라) 3가지 색으로 각각 `Initialize()` 호출 →
      전부 무채색 아트(`LingeringZone_0`)에 `SpriteRenderer.color`로 정확히 해당 색(알파 0.35)이
      곱해져 표시됨을 확인.
- [x] **크기 검증**: 3색 전부 `transform.localScale × sprite.bounds.size`가 `radius(2.0)×0.9×0.2=0.36`으로
      완전히 동일. 폴백 원에서도 동일한 0.36 확인(이중 확대 없음).
- [x] **회귀 - 틱 데미지/지속시간/보스 피해**: 가짜 적+보스 배치 후 실측, 틱 간격(0.1초)마다 데미지(7)가
      적/보스 양쪽에 정확히 들어가고, `remainingDuration`이 지정한 `duration`(0.3초) 이하로 내려가는
      순간 `Destroy(gameObject)`가 호출됨을 필드값으로 확인(이 환경은 `Destroy()`의 실제 반영이 프레임
      종료까지 지연되지만, 그 호출 자체와 로직 흐름은 필드값으로 명확히 확인됨).

### 바이올린 칼날

      **한 글자도 변경되지 않음**(이전 빔 애니메이션 세션에서 이미 참격/보스/틱 피해 로직을 실측

**부가 관찰**: 에디터 창 포커스 상실로 인한 `Time.time` 정체/`Destroy()` 지연 반영 환경 특성은 다른

**결론**: 프렌치호른 회전+피벗 보정, 잔류 장판 색 틴트+크기, 바이올린 칼날 크기 정규화 전부 설계
