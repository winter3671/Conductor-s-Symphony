# 크레센도(범위 공격 증가) 패시브 - 나머지 9종 악기 연동 검증 가이드

이 문서는 **Unity MCP가 연결된 별도 Claude Code 세션**에서 이번 수정을 실측 검증할 때 참고하는
절차서입니다. 아직 커밋하지 않은 상태입니다.

검증이 끝나면 이 파일 하단에 결과를 추가로 append해주세요.

## 0. 무엇을 고쳤나

드럼에만 반영했던(`Docs/archive/drum_range_visualization_test_guide.md` 참고) 크레센도(Crescendo,
"모든 공격 범위 +10%/Lv, 최대 +50%") 패시브를 나머지 9종 악기에도 전부 연결했습니다. 반복되는
null-체크를 없애려고 `CombatTargetingUtility.GetRangeMultiplier()` 헬퍼를 새로 만들었고(드럼 2곳도
이걸 쓰도록 같이 정리), 이후 각 악기 이펙트가 자기 "사거리/반경"을 계산하는 지점에 이 배율을 곱하는
식으로 반영했습니다. 데미지 계산식은 전부 그대로 - `radius`/`range` 변수에만 배율을 곱했습니다.

### 악기별 반영 지점

| 악기 | 반영한 파라미터 | 반영 안 한 것 |
|---|---|---|
| 피아노 | 빔 `maxRange`(9f, 이제 레벨 무관하게 배율만 적용) | - |
| 벨 | 8방향 빔 `range`(2.5f×레벨) | - |
| 마림바 | 파동 `maxRange`(10f) | - |
| 글록켄슈필 | 스플래시 `splashRadius`(0.6f+레벨) | 타겟팅 자체(체력 최고 적 탐색)는 원래 거리 제한 없음 |
| 바이올린 | 궤도 `radius`(1.4f×레벨), 참격 `range`(6f), **Lv5 잔향 반경(0.6f)** | - |
| 프렌치호른 | 부채꼴 `range`(3.0f×레벨) | `halfAngleDeg`(각도는 범위 스탯 아님) |
| 첼로 | 중력장 `radius`(1.8f×레벨) | - |
| 팀파니 | 캐논 `initialRadius`(1.0f×레벨), 융단폭격 스플래시(0.7f)+랜덤 오프셋(±1.0) **동일 배율**, **Lv5 지진지대 반경(1.0f)** | - |
| 플루트 | 흡입 `radius`(2.0f×레벨) | 당기는 힘(`pullStrength`)·유지시간(`duration`)은 범위 아님 |

### 팀파니 융단폭격 - "동일 배율" 결정에 대해

스플래시 반경과 랜덤 오프셋 산포 범위 중 하나만 배율을 적용하면 고정 표적 기준 명중률이 크게
바뀝니다(스플래시만 늘리면 명중률 급상승, 오프셋만 늘리면 명중률 급하락 - 원 넓이/사각형 넓이
비율이 깨지기 때문). 이미 튜닝된 DPS/명중률 밸런스(`archive/dps_balance_test_result.md` §2-5 참고,
팀파니 저레벨 명중률 이슈)를 건드리지 않기 위해 **둘 다 정확히 같은 배율**을 곱하도록 결정했습니다
(2026-08-06, 대화로 확정). 수학적으로 이 경우 명중 확률(약 38.5%)은 배율과 무관하게 그대로
유지되고, "커버하는 절대 면적"만 넓어집니다.

- `Assets/Scripts/Combat/DrumAuraController.cs`,
  `Assets/Scripts/Combat/InstrumentAttacks/DrumBeatBangEffect.cs` (수정 — 기존 인라인 null-체크를

- `Assets/Scripts/Combat/InstrumentAttacks/{PianoBeamEffect,BellStarburstEffect,MarimbaWaveEffect,
  GlockenspielStarfallEffect,ViolinOrbitEffect,FrenchHornConeEffect,CelloGravityFieldEffect,

## 1. 사전 준비

1. `refresh_unity(mode=force, compile=request)` → `read_console`로 컴파일 에러 확인.
2. 크레센도 패시브는 `PassiveStatManager.Instance.AcquireOrUpgrade(PassiveStatType.Crescendo)`를
   반복 호출해 강제로 레벨을 올려 테스트할 수 있습니다(Lv5 = 배율 1.5).
3. 각 악기 판정은 `EnemySpawner.activeEnemies`에 리플렉션으로 정지 테스트 몹을 정확한 거리에 등록해
   HP 변화로 확인하는 방식을 그대로 재사용하면 됩니다(드럼 검증 때와 동일한 방법론).

## 2. 검증 항목

### 배율 반영 확인 (9종 공통 패턴)
각 악기마다 크레센도 Lv0(배율 1.0)과 Lv5(배율 1.5) 상태에서 실제 판정 반경이 정확히 1.5배
차이 나는지 확인해주세요. 판정 반경 안/밖 경계에 정지 몹을 세워두고 피해 여부로 교차 확인하는 걸
권장합니다(비주얼만 보고 판단하지 말 것).

- [ ] 피아노: 빔이 도달하는 최대 거리가 1.5배로 늘어나는지 (관통 개수/발사 수는 그대로인지도 회귀 확인)
- [ ] 벨: 8방향 빔 사거리가 1.5배로 늘어나는지
- [ ] 마림바: 파동이 도달하는 최대 거리가 1.5배로 늘어나는지
- [ ] 글록켄슈필: 스플래시 반경이 1.5배로 늘어나는지 (주 타겟 착탄 데미지는 그대로인지도 회귀 확인)
- [ ] 바이올린: 궤도 칼날 반경 1.5배, 릴리즈 참격 사거리 1.5배, **Lv5 잔향 장판 반경도 1.5배**
      (3개 전부 개별 확인)
- [ ] 프렌치호른: 부채꼴 사거리 1.5배로 늘어나되, 부채꼴 각도(120°/180°)는 배율과 무관하게 그대로인지
- [ ] 첼로: 중력장 반경 1.5배 (감속/끌어당김 로직은 반경만 커지고 세기는 그대로인지도 회귀 확인)
- [ ] 팀파니: 캐논 반경 1.5배, **Lv5 지진지대 반경도 1.5배**
- [ ] 팀파니 융단폭격: 스플래시 반경과 랜덤 오프셋 산포가 함께 1.5배로 늘어나는지, 그리고 고정
      표적 하나를 세워두고 여러 번(예: 30회) 반복 착탄시켜 명중 횟수를 셌을 때 크레센도 적용
      전/후로 명중률이 눈에 띄게 달라지지 않는지(대략 38.5% 근처로 유지되는지 - 정확한 수치보다는
      "배율 적용 전후 큰 차이가 없다"는 것 확인이 목적)
- [ ] 플루트: 흡입 반경 1.5배로 늘어나는지 (당기는 힘 세기·지속시간은 배율과 무관하게 그대로인지도
      회귀 확인)

### 회귀

## 3. 알려진 참고 사항

- **DPS 밸런스 재검증은 하지 않았습니다**: 이번 변경은 "범위"만 건드렸고 "초당 데미지"는 건드리지
  않았지만, 사거리가 넓어지면 다수 적 상황에서 명중 횟수/도달 범위가 늘어나 체감 DPS가 높아질 수
  있습니다. `dps_balance_gap_analysis.md`의 실측은 전부 "크레센도 미보유" 기준이었으므로, 크레센도를
  적극적으로 찍는 빌드의 체감 밸런스는 별도로 확인이 필요할 수 있습니다.
- **팀파니 융단폭격 명중률 수학은 이론값입니다**: "동일 배율이면 명중률이 유지된다"는 원 넓이/사각형
  넓이 비율 계산은 정지 표적 기준 이론치입니다. 실제로는 스플래시가 커지면 여러 마리가 몰려있을 때
  동시 피격 범위도 넓어지므로, 다수 적 상황에서는 체감상 더 강해질 수 있습니다(의도된 효과로 보입니다).

## 4. 검증 결과 (Unity MCP 세션, 2026-08-06)

**환경**: Unity 6000.5.5f1, `Assets/Scenes/Gameplay.unity`, Play Mode(`manage_editor(pause)` +
`UnityEditor.EditorApplication.Step()` 수동 프레임 진행 방식 사용 - 이전 두 세션에서 에디터 언포커스 시
`Update()`가 멈추는 문제를 겪어서 이번엔 처음부터 이 방식으로 진행). `refresh_unity(force,
compile=request)` + `read_console` 확인 결과 컴파일 에러 없음. 세션 전체에서 프로젝트 코드 관련
콘솔 에러 0건.

**방법**: 각 악기 이펙트(`PianoBeamEffect` 등)를 `execute_code`로 직접 `Execute()`/`Init()`/
`Initialize()` 호출해 스폰된 실제 판정 오브젝트(`PiercingBeamProjectile.maxRange`,
`AreaImpactEffect.radius`, 각 홀드 이펙트 자신의 `radius`/`range` 필드 등 - 전부 실제 피격 판정에
쓰이는 바로 그 필드)를 리플렉션으로 직접 읽었습니다. `PassiveStatManager`의 private `acquired`
리스트를 리플렉션으로 조작해 크레센도 레벨을 0↔5로 자유롭게 오갈 수 있게 해서(공개 API는
업그레이드만 가능하고 다운그레이드가 없음), 같은 Play 세션 안에서 Lv0 기준값과 Lv5 배율 적용값을
전부 비교했습니다. 대표적으로 피아노 빔(투사체 도달거리)과 팀파니 융단폭격(명중률)은 정지 테스트
몹을 실제 배치해 HP 변화로도 교차 검증했습니다.

| 벨 | 8방향 빔 range | 2.500 | 3.750 |

| 바이올린 | 참격 range | 6.000 | 9.000 |

- [x] **피아노**: 위 표대로 정확히 1.5배. 실제 판정으로도 교차 확인 — 크레센도 Lv5(range=13.5)
      상태에서 13.0 거리 몹은 피격, 14.0 거리 몹은 무피해. 관통(pierce)/발사 수(shots)는 배율과
      무관한 별도 파라미터라 애초에 영향 없음(코드 확인).
- [x] **벨**: 정확히 1.5배 확인.
- [x] **마림바**: 정확히 1.5배 확인.
- [x] **글록켄슈필**: 스플래시 반경 정확히 1.5배. 주 타겟 착탄 데미지(`scaledDamage`)는 크레센도
      Lv0/Lv5 양쪽 다 10으로 동일 — 회귀 없음.
- [x] **바이올린**: 궤도 칼날 반경·참격 사거리·Lv5 잔향 반경 3개 전부 개별 확인, 전부 공식과 정확히 일치.
- [x] **프렌치호른**: 부채꼴 사거리는 1.5배(3.000→4.500)로 늘어나지만, `halfAngleDeg`는 크레센도
      Lv0/Lv5 양쪽 다 60.0으로 동일 — 각도가 범위 배율과 무관함을 확인(회귀 없음).
- [x] **첼로**: 정확히 1.5배 확인.
- [x] **팀파니 캐논**: 정확히 1.5배 확인.
- [x] **팀파니 Lv5 지진지대**: 정확히 1.5배 확인.
- [x] **팀파니 융단폭격**: 스플래시 반경(0.700→1.050)과 랜덤 오프셋 산포(25회 샘플 최대치
      1.393→1.888, 이론상 한도 1.414→2.121과 부합) 둘 다 함께 커짐을 확인. 고정 표적 1개에
      40회 반복 착탄시켜 명중률 측정 — Lv0크레센도 25.0%(10/40), Lv5크레센도 37.5%(15/40). 둘 다
      이론치(≈38.5%) 근방이고, 40회 표본의 이항분포 표준편차(≈±7.7%p)를 감안하면 서로 유의미하게
      다르다고 보기 어려움 — "배율 적용 전후 명중률 큰 차이 없음" 조건 충족.
  - **테스트 중 발견한 방법론 함정(기록용, 코드 버그 아님)**: 처음 이 테스트를 돌렸을 때 명중률이
    52.5%/5.0%로 이론치와 동떨어지게 나왔습니다. 원인은 백그라운드에서 실제로 진행 중이던 잡몹
    스폰(`EnemySpawner`)이 만든 진짜 몹들이 테스트용 고정 표적보다 플레이어에 더 가까워
    `GetNearestEnemy()`가 그 몹(계속 움직임)을 조준 기준(`targetPos`)으로 잡아버린 것이었습니다 -
    테스트 표적이 실제 착탄 중심에서 벗어나 있었던 것. `EnemySpawner.activeEnemies`를 비우고
    스포너를 일시적으로 비활성화한 뒤 재측정하니 위 결과처럼 정상 범위로 나왔습니다.
- [x] **플루트**: 정확히 1.5배 확인.
