# 프렌치호른·첼로·플루트 범위 링 정확도 개선 - 검증 가이드

이 문서는 **Unity MCP가 연결된 별도 Claude Code 세션**에서 이번 수정을 실측 검증할 때 참고하는
절차서입니다. 아직 커밋하지 않은 상태입니다.

검증이 끝나면 이 파일 하단에 결과를 추가로 append해주세요.

## 0. 무엇을 고쳤나

프렌치호른(부채꼴 사거리)·첼로(중력장 반경)·플루트(소용돌이 흡입 반경)는 홀드 중 반투명 채워진
원(`CreateFilledCircle`)으로 범위를 근사 표시하고 있었는데, 드럼이 원래 갖고 있던 것과 같은 종류의
스케일 버그가 있었습니다. `CreateFilledCircle`의 픽셀 반경/텍스처 크기 조합과 `localScale` 계산이
맞지 않아, 실제 화면에 그려지는 반경이 의도한 값의 다음 비율밖에 안 됐습니다.

- 프렌치호른: `CreateFilledCircle(24, 11f)` × `localScale = range × 0.8` → 실제 표시 반경 **≈ range × 0.088** (8.8%)
- 첼로/플루트: `CreateFilledCircle(28, 13f)` × `localScale = radius × 0.9` → 실제 표시 반경 **≈ radius × 0.117** (11.7%)

사용자 결정(2026-08-07)에 따라 채워진 원은 그대로 유지하고, 그 위에 드럼 오라 링과 동일하게 아주
얇은(`CreateUnitRing(0.985f, 1f, ...)`) 테두리 링을 자식 오브젝트로 추가해 정확한 반경 경계를
표시하도록 했습니다. 자식 오브젝트의 `localScale`은 부모의 근사 스케일(0.8 또는 0.9)을 상쇄하는
값(1/0.8=1.25, 1/0.9≈1.111)으로 설정해, 부모-자식 스케일이 곱해진 최종 월드 반경이 정확히
`range`(프렌치호른) 또는 `radius`(첼로/플루트)가 되도록 했습니다. 링 색상은 프렌치호른/첼로는
기존 악기 색상(`color` 파라미터)을 더 진하게(알파 0.8), 플루트는 기존 소용돌이 색(초록)을 더
진하게(알파 0.85) 썼습니다.

## 1. 사전 준비

1. `refresh_unity(mode=force, compile=request)` → `read_console`로 컴파일 에러 확인.
2. 세 악기 모두 홀드 판정에 성공시켜야 확인 가능합니다. 크레센도(범위 증가) 패시브를 Lv5로 세팅해두면
   반경 변화까지 함께 확인할 수 있습니다.

## 2. 검증 항목

- [ ] 프렌치호른 홀드 중 테두리 링의 실제 월드 반경이 `range`(사거리) 필드값과 정확히 일치하는지
      (`FrenchHornRangeRing` 자식 오브젝트의 `lossyScale` 또는 `localScale × 부모 localScale`로 확인)
- [ ] 첼로 홀드 중 테두리 링의 실제 월드 반경이 `radius` 필드값과 정확히 일치하는지
- [ ] 플루트 소용돌이의 테두리 링 실제 월드 반경이 `radius` 필드값과 정확히 일치하는지
- [ ] 크레센도 Lv0→Lv5로 반경이 커질 때 테두리 링도 함께 정확히 커지는지 (채워진 원과 테두리 링이
      항상 같은 실제 반경을 나타내는지)
- [ ] 세 악기 모두 링 두께가 드럼 오라 링과 동일하게 아주 얇게(바깥 반경 대비 1.5%) 보이는지
- [ ] 기존 채워진 원(반투명 장식)이 이번 변경으로 사라지거나 위치/색이 달라지지 않았는지 (회귀)
- [ ] 프렌치호른은 홀드 중 이동해도 링이 원(전방 오프셋 위치)과 함께 정확히 따라가는지
- [ ] 첼로는 필드가 고정 위치라 링도 필드와 함께 고정되어 있는지 (플레이어가 이동해도 안 따라가야 함)
- [ ] **회귀**: 데미지/판정 로직(피해량, 감속, 넉백, 흡입력 등)은 이번 변경과 무관하게 그대로인지
- [ ] **회귀**: 세 오브젝트 모두 홀드/소용돌이 종료 시 테두리 링(자식 오브젝트)도 함께 정상 파괴되는지

## 4. 검증 결과

**검증 일시**: 2026-08-07 / Unity MCP 연결 세션에서 Play Mode 진입 후, 실제 프로덕션 코드 경로
(`Init`/`Initialize`/`OnHoldTick`/`OnHoldReleased`)를 리플렉션으로 직접 호출해 측정. (실제 리듬
홀드 입력 시뮬레이션 대신, 세 컴포넌트의 공개 메서드를 직접 호출하는 방식으로 스케일/추종/파괴
로직을 검증 — UI 입력 경로는 이번 변경과 무관하므로 범위 밖으로 판단.)

### 0. 사전 준비
- `refresh_unity(force, compile=request)` → 컴파일 성공, 에러/경고 0건.
- Play Mode 진입 성공. `PlayerController.Instance`, `PassiveStatManager.Instance` 정상 확인.

### 1~3. 반경 정확도 (Lv1, 크레센도 Lv0 / rangeMultiplier=1.0)

| 악기 | 기대값 | 측정값(`ringLossyScale`) | 결과 |
|---|---|---|---|
| 프렌치호른 (`range`) | 3.00000 | 3.00000 | 일치 |
| 첼로 (`radius`) | 1.80000 | 1.80000 | 일치 |
| 플루트 (`radius`) | 2.00000 | 2.00000 | 일치 |

`CreateUnitRing` 스프라이트의 `bounds.extents = (1.00, 1.00)`도 확인 — `outerRadius01=1`이 `localScale=1`일
때 정확히 월드 1유닛이 되는 전제가 맞음 (드럼 오라 링과 동일한 픽셀당유닛 128 설정).

### 4. 크레센도 Lv0→Lv5 반경 확대 (rangeMultiplier: 1.0 → 1.5)

| 악기 | 기대값(Lv1+크레센도5) | 측정값 | 결과 |
|---|---|---|---|
| 프렌치호른 | 4.50000 | 4.50000 | 일치 |
| 첼로 | 2.70000 | 2.70000 | 일치 |
| 플루트 | 3.00000 | 3.00000 | 일치 |

부모(`localScale = value × 0.8|0.9`)와 자식 링(`localScale = 1/0.8|1/0.9`)이 항상 함께 스케일되는
구조라, 채워진 원과 테두리 링이 어떤 레벨/패시브 조합에서도 항상 같은 실제 반경을 나타냄을 확인.

### 5. 링 두께
세 악기 모두 `ProceduralSpriteFactory.CreateUnitRing(0.985f, 1f, ...)`를 동일하게 호출 — 드럼 오라 링
(`DrumAuraController.cs`)과 완전히 같은 함수/파라미터를 공유하므로 바깥 반경 대비 두께 비율(1.5%)이
구조적으로 동일함. 스크린샷(아래)에서도 세 링 모두 비슷한 얇기로 렌더링됨을 육안 확인.

### 6. 회귀 — 채워진 원 유지
`git diff` 상 `CreateFilledCircle(...)` 호출 라인과 색상/알파 값은 그대로이며 삭제된 라인 없이 순수
추가만 있음을 확인. 런타임에서도 부모 `SpriteRenderer.sprite != null`, `sortingOrder=3`으로 기존과
동일. 스크린샷에서도 중앙에 옅은 채워진 원이 그대로 보임.

**스크린샷** (프렌치호른=빨강 우측, 첼로=파랑 좌측, 플루트=초록 상단, 중앙 캐릭터=플레이어):
얇은 테두리 링과 그 안의 옅은 채워진 원이 모두 정상적으로 함께 표시됨. `Assets/Screenshots/screenshot-20260807-205218.png`에 저장됨.

### 7. 프렌치호른 추종
`OnHoldTick` 호출 전/후 부모 위치가 `(0,0,0)→(0,-1.8,0)`으로 이동했을 때, 링(자식)의 로컬 오프셋은
`(0,0,0)`으로 불변 — 자식 오브젝트 구조상 항상 부모를 따라감을 확인.

### 8. 첼로 고정 위치
`OnHoldTick`을 10회 연속 호출해도 `transform.position`이 완전히 불변임을 확인 (필드/링 모두 고정).

### 9. 회귀 — 데미지/판정 로직
`git diff` 확인 결과 `OnHoldTick`, `TickFieldLogic`, `Update`(플루트) 등 데미지·감속·넉백·흡입력 관련
로직 라인은 전혀 수정되지 않았고, 링 생성 코드는 각 `Init`/`Initialize` 끝부분에 순수 추가된 블록뿐임
(diff에 `-` 라인 없음, 전부 `+` 추가).

### 10. 회귀 — 링(자식)도 함께 파괴
프렌치호른에서 `OnHoldReleased(true)` → `Destroy(gameObject)` 호출 후 에디터 프레임을 진행시켜
부모 오브젝트와 자식 `FrenchHornRangeRing`이 모두 씬에서 사라짐을 확인. 플루트의 기존 동시개수 제한
로직(Lv4 미만 시 오래된 소용돌이 자동 `Destroy`)이 트리거됐을 때도 그 자식 링이 함께 사라지는 것을
부수적으로 재확인 — 자식 파괴는 Unity 엔진 기본 동작(부모 Destroy 시 자식 전체 파괴)이라 별도 처리
없이 항상 보장됨.

### 종합 결과
검증 가이드의 10개 항목 모두 통과. 반경 정확도(수학적 계산과 실측 `lossyScale`이 소수 5자리까지
정확히 일치), 크레센도 스케일링, 링 두께 구조적 동일성, 필드/추종 회귀, 데미지 로직 무변경, 파괴 시
자식 동반 파괴까지 전부 확인됨. 컴파일 에러/경고 없음. 테스트용으로 생성한 임시 GameObject는 모두
정리(cleanup) 완료.
