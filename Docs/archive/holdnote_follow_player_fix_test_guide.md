# 홀드 노트가 이동 중 판정 링을 따라가지 않던 버그 - 검증 가이드

이 문서는 **Unity MCP가 연결된 별도 Claude Code 세션**에서 이번 수정을 실측 검증할 때 참고하는
절차서입니다. 아직 커밋하지 않은 상태입니다.

검증이 끝나면 이 파일 하단에 결과를 추가로 append해주세요.

## 0. 무엇을 고쳤나

실플레이 중 발견된 버그: 홀드(롱노트) 판정에 성공한 뒤 키를 계속 누른 채로 화살표 키로 이동하면,
노트(머리+꼬리)가 그 자리에 멈춰있고 플레이어(와 흰색 판정 링)만 이동해버려서 노트가 판정 링에서
눈에 띄게 벗어나 보였습니다.

원인은 `RhythmNote.Update()`가 `isHolding == true`일 때 꼬리 비주얼(`UpdateTailVisual()`)만 갱신하고
`UpdatePosition()`은 다시 호출하지 않았기 때문입니다. `BeginHold()` 시점에 딱 한 번만 위치를
판정 반경으로 고정하고 그 뒤로는 손대지 않아서, 플레이어가 움직이면 노트는 그 자리에 남았습니다.
`Assets/Scripts/Rhythm/RhythmNote.cs`의 `Update()`에서 홀드 중에도 매 프레임 `UpdatePosition(1f)`를
호출하도록 한 줄 추가했습니다 - 판정 링(`JudgmentRing`)처럼 항상 플레이어 기준 상대 위치를 유지합니다.

이번 수정은 노트의 시각적 위치(`transform.position`)만 다루고, 실제 공격 이펙트(바이올린 칼날/
프렌치호른 부채꼴 등)는 원래도 각자 `PlayerController.Instance.transform`을 따로 참조해서 플레이어를
잘 따라가고 있었으므로 영향 없습니다 - 순수하게 "노트 표시 위치"만 고치는 변경입니다.

## 1. 사전 준비

1. `refresh_unity(mode=force, compile=request)` → `read_console`로 컴파일 에러 확인.
2. 홀드 5종(바이올린/프렌치호른/첼로/팀파니/플루트) 중 아무거나 홀드 판정에 성공시킨 뒤, 홀드가
   끝나기 전에 화살표 키로 이동해보면 재현/확인이 가장 빠릅니다.

## 2. 검증 항목

- [ ] 홀드 판정 성공 후 이동하면 노트(머리+꼬리)가 플레이어(흰색 판정 링) 위치를 계속 따라가는지
- [ ] 이동 중에도 꼬리가 정상적으로 줄어드는지(진행률 계산과 무관한 변경이라 회귀 없어야 함)
- [ ] 홀드 중 가만히 있을 때는 기존과 동일하게 동작하는지 (제자리 홀드가 회귀 없는지)
- [ ] 홀드를 끝까지 채우거나 조기 이탈했을 때 노트가 정상적으로 사라지는지
- [ ] **회귀**: 접근 구간(홀드 시작 전, 아직 내려오는 중)의 노트 이동은 이번 변경과 무관하게 기존과
      동일하게 동작하는지 (건드린 코드는 `isHolding == true`일 때만 실행됨)
- [ ] **회귀**: 각 악기의 실제 공격 판정(칼날 타격, 부채꼴 타격 등)은 플레이어 위치를 따라가며
      정상 동작하는지 - 이번 변경 이전에도 이미 정상이었어야 함(이펙트 자체가 노트 위치와 무관하게
      플레이어를 직접 참조하므로)

## 4. 검증 결과 (Unity MCP 세션, 2026-08-06)

**환경**: Unity 6000.5.5f1, `Assets/Scenes/Gameplay.unity`, Play Mode(`manage_editor(pause)` +
`EditorApplication.Step()` 수동 프레임 진행). `refresh_unity(force, compile=request)` +
`read_console` 확인 결과 컴파일 에러 없음. 세션 전체 콘솔 에러 0건.

**방법**: `RhythmManager.SpawnNoteForLane()`이 호출하는 것과 동일한 `RhythmNote.Initialize()` /
`BeginHold()` / `TickHold()`를 `execute_code`로 직접 호출해 홀드 노트를 만들고,
`PlayerController.Instance.transform.position`을 직접 옮겨 "화살표 키 이동"을 재현했습니다.

- [x] **홀드 성공 후 이동 시 노트가 플레이어(판정 링)를 따라감**: `BeginHold()` 직후 노트 위치가
      `player.position + laneDirection*judgmentRadius`와 정확히 일치했고, 플레이어를 `(2, 1, 0)`만큼
      옮긴 뒤에도 노트 위치가 새 플레이어 위치 기준으로 정확히 재계산됨을 확인
      (`(0.60,0,0)→(2.60,1.00,0)`, 오차 0). 판정 링(`JudgmentRing`)의 실제 시각적 정점(LineRenderer
      world-space vertex)도 같은 새 위치를 기준으로 그려짐을 확인해 노트와 판정 링이 계속 같은
      자리에 있음을 교차 확인했습니다.
  - **테스트 중 착각했던 부분(기록용)**: 처음에 `JudgmentRing`의 `transform.position`을 읽어서
    "제자리에 고정되어 있다(버그처럼 보임)"고 순간 오해했는데, `JudgmentRing`은 자기 GameObject의
    transform이 아니라 `LineRenderer`의 world-space 정점 좌표로 그려지는 구조라 `transform.position`
    자체는 원래도 안 움직이는 게 정상입니다(코드 확인). `LineRenderer.GetPosition(0)`으로 다시
    읽으니 새 플레이어 위치 기준으로 정확히 그려지고 있었습니다 — 실제 버그 아님, 제 확인 방법 실수.
- [x] **이동 중 꼬리도 정상적으로 줄어듦**: 4초 홀드 중 50% 진행(`TickHold(2.0)`) + 동시에 플레이어
      이동 후 확인 — 꼬리 길이 3.400→1.700(정확히 절반)로 줄었고, 노트 위치도 동시에 새 플레이어
      위치를 정확히 따라감. 두 로직이 서로 간섭 없이 함께 동작.
- [x] **제자리 홀드는 회귀 없음**: 플레이어를 전혀 움직이지 않은 채 5프레임 진행 — 노트 위치가
      소수점 단위까지 완전히 동일하게 유지됨(매 프레임 재계산해도 흔들림/드리프트 없음).
- [x] **완료/조기 이탈 시 정상 소멸**: 홀드 완료(`TickHold`로 지속시간 초과) 시 꼬리가 먼저
      비활성화된 뒤 `DestroyNote()`로 정상 파괴, 조기 이탈(이동 중 도중에 릴리즈)도 에러 없이
      정상 파괴됨을 확인.
- [x] **회귀: 접근 구간(홀드 시작 전) 이동 대응**: `BeginHold()` 호출 전(`isHolding==false`)
      상태에서 플레이어를 이동시켜도 노트가 그대로 따라감 — 이 코드 경로는 원래도 매 프레임
      `targetTransform.position`을 참조하고 있어 이번 변경과 무관하게 항상 정상이었음을 확인
      (건드린 코드는 `isHolding==true` 분기뿐이라는 문서 설명과 일치).
- [x] **회귀: 실제 공격 이펙트는 플레이어를 계속 따라감**: `ViolinOrbitEffect`를 직접 스폰해 확인 —
      `OnHoldTick()`마다 `PlayerController.Instance.transform.position`을 직접 읽어와 자기 위치를
      갱신하므로, 플레이어 이동 후에도 정확히 새 위치로 따라감. 노트의 시각적 위치와는 완전히 독립된
      로직이라 이번 수정과 무관하게 원래부터 정상이었음을 재확인.

**버그**: 발견되지 않았습니다. `RhythmNote.cs`의 수정(홀드 중 매 프레임 `UpdatePosition(1f)` 추가)은
문서에 적힌 대로 정확히 동작하며, 제자리 홀드·접근 구간·완료/조기이탈·공격 이펙트 어디에도 회귀가
없습니다.
