# 알레그로(쿨타임 감축)/페르마타(지속시간 증가) 패시브 연동 - 검증 가이드

이 문서는 **Unity MCP가 연결된 별도 Claude Code 세션**에서 이번 작업을 실측 검증할 때 참고하는
절차서입니다. 아직 커밋하지 않은 상태입니다.

검증이 끝나면 이 파일 하단에 결과를 추가로 append해주세요.

## 0. 무엇을 고쳤나

크레센도(범위 증가) 패시브를 전 악기에 연동한 직전 작업과 같은 이유로, 알레그로(쿨타임 감축)와
페르마타(지속시간 증가) 두 패시브도 완전히 죽어있었습니다(`Docs/team_review_needed.md` 1-1 항목,
그리고 이후 실시한 전체 패시브 감사에서 재확인). 이번 작업은 이 두 패시브를 실제 발동 주기/지속시간을
가진 모든 메커니즘에 연동했습니다.

`CombatTargetingUtility.cs`에 두 헬퍼를 추가했습니다:
- `GetCooldownMultiplier()`: `1f - GetCooldownReductionFraction()` (0~1, 작을수록 더 자주 발동).
  주기적으로 반복 발동하는 tick/interval 값에 곱합니다 (예: `interval *= 이 값`).
- `GetDurationMultiplier()`: `GetDurationMultiplier()` 그대로 (1.0~1.75, 클수록 오래 유지). 잔류
  장판/필드의 duration 값에 곱합니다.

**적용 대상 (7개 파일)**:

| 악기 | 알레그로(주기 단축) | 페르마타(지속시간 증가) |
|---|---|---|
| 드럼 | 오라 tick interval | - |
| 첼로 | 중력장 tick interval | Lv4 잔류시간(linger duration) |
| 프렌치호른 | 부채꼴 tick interval | - |
| 팀파니 | 폭격 간격(bombardInterval), Lv5 지진지대 tick | Lv5 지진지대 duration |
| 바이올린 | 칼날 재타격 쿨다운(HitCooldown), Lv5 잔향 tick | Lv5 잔향 duration |
| 벨 | Lv5 잔향 tick | Lv5 잔향 duration |
| 플루트 | - | 소용돌이 유지시간(duration) |

**적용하지 않은 것 (판단 근거)**:
- 글록켄슈필/팀파니의 착탄 지연(delay, 0.05~0.15초) - 사용자 결정으로 알레그로 대상에서 제외.
  "발동 주기"가 아니라 "타격이 화면에 보이기까지의 연출 지연"이라 성격이 다름.
- 플루트/바이올린 등의 `pullStrength`, `slowFraction` 같은 세기(magnitude) 값 - 범위/주기/지속시간이
  아니라 크레센도·알레그로·페르마타 어느 것과도 무관.
- 홀드 노트 자체의 `HoldDurationSeconds` - 페르마타를 곱하면 늘어난 길이만큼 플레이어가 더 오래
  버텨야 해서 오히려 불리해지므로 절대 대상에서 제외.

## 1. 사전 준비

1. `refresh_unity(mode=force, compile=request)` → `read_console`로 컴파일 에러 확인.
2. `PassiveStatManager`에 알레그로/페르마타 레벨을 직접 세팅해서(예: Lv5) 배율을 극대화한 상태로
   비교하면 효과가 뚜렷합니다. 알레그로 Lv5 = 배율 0.70(interval ×0.70), 페르마타 Lv5 = 배율 1.75.

## 2. 검증 항목

- [ ] 알레그로 Lv0(배율 1.0)과 Lv5(배율 0.70) 상태에서 각 tick interval 값이 정확히 0.70배로
      줄어드는지 (드럼 오라, 첼로 필드, 프렌치호른 부채꼴, 팀파니 폭격/지진지대, 바이올린
      재타격쿨다운/잔향, 벨 잔향)
- [ ] 페르마타 Lv0(배율 1.0)과 Lv5(배율 1.75) 상태에서 각 duration 값이 정확히 1.75배로 늘어나는지
      (첼로 잔류시간, 팀파니 지진지대, 바이올린 잔향, 벨 잔향, 플루트 소용돌이 유지시간)
- [ ] 데미지 값(damage, tickDamage)은 이번 변경과 무관하게 그대로인지 (배율이 곱해지지 않아야 함)
- [ ] 홀드 노트의 `HoldDurationSeconds`/판정 타이밍이 페르마타와 무관하게 그대로인지
- [ ] **회귀**: 크레센도(범위) 배율이 여전히 정상 동작하는지 (이번 변경으로 같은 줄에 곱셈이
      추가되었으므로 곱셈 순서/누락 확인)
- [ ] **회귀**: 알레그로/페르마타가 모두 Lv0(패시브 미장착)일 때 모든 수치가 이전과 완전히 동일한지

## 4. 검증 결과 (Unity MCP 세션, 2026-08-06)

**환경**: Unity 6000.5.5f1, `Assets/Scenes/Gameplay.unity`, Play Mode(`manage_editor(pause)` +
`EditorApplication.Step()` 수동 프레임 진행). `refresh_unity(force, compile=request)` 확인 결과
컴파일 에러 없음(첫 시도는 60초 타임아웃이 떴으나 재확인 결과 컴파일은 이미 정상 완료된 상태였음 -
에디터 언포커스로 인한 응답 지연으로 추정, 실제 에러 아님). 세션 전체 콘솔 에러 0건.

**방법**: `PassiveStatManager`의 private `acquired` 리스트를 리플렉션으로 조작해 알레그로/페르마타
레벨을 0↔5로 자유롭게 오가며, 각 이펙트를 `execute_code`로 직접 `Init()`/`Execute()`/`OnHoldTick()`
호출해 실제 판정에 쓰이는 필드(`bombardInterval`, `lingerTimer`, `LingeringZoneEffect.duration`/
`tickInterval`, `FluteVortexEffect.duration` 등)를 리플렉션으로 읽었습니다. `interval` 값이 별도
필드로 저장되지 않고 `Update()`/`OnHoldTick()` 안에서 매번 인라인으로 계산되는 3곳(드럼 오라, 첼로
필드, 프렌치호른 부채꼴)은 `tickTimer` 필드의 "리셋 경계"를 직접 탐지하는 방식으로 확인했습니다
(임계값 근처 두 번 나눠 호출해 안 튀는지/튀는지 확인, 드럼은 `EditorApplication.Step()`으로 실제
프레임을 여러 번 돌리며 `tickTimer`가 몇 스텝마다 리셋되는지 카운트).

### 알레그로(쿨타임 감축) — Lv0(배율 1.0) vs Lv5(배율 0.70)

| 악기 | 파라미터 | Lv0 | Lv5 | 확인 방식 |
|---|---|---|---|---|
| 드럼 | 오라 tick interval | ~0.500s (23~26스텝×0.02s) | ~0.36s (18스텝×0.02s, 기대 0.350) | Step 리셋 주기 측정 |
| 첼로 | 필드 tick interval | 정확히 0.400 | 정확히 0.280 | tickTimer 경계 탐지 |
| 프렌치호른 | 부채꼴 tick interval | 정확히 0.200 | 정확히 0.140 | tickTimer 경계 탐지 |
| 팀파니 | 폭격 간격(bombardInterval) | 0.650 | 0.455 | 필드 직접 읽기 |
| 팀파니 Lv5 | 지진지대 tick | 0.500 | 0.350 | 필드 직접 읽기 |
| 바이올린 | 재타격 쿨다운(hitCooldowns 값) | 0.350 | 0.245 | 실제 히트 후 딕셔너리 값 읽기 |
| 바이올린 Lv5 | 잔향 tick | 0.400 | 0.280 | 필드 직접 읽기 |
| 벨 Lv5 | 잔향 tick | 0.300 | 0.210 | 필드 직접 읽기 |

- [x] 8개 항목 전부 정확히 0.70배(드럼은 스텝 양자화 오차 범위 내) 확인.

### 페르마타(지속시간 증가) — Lv0(배율 1.0) vs Lv5(배율 1.75)

| 악기 | 파라미터 | Lv0 | Lv5 |
|---|---|---|---|
| 첼로 Lv4 | 잔류시간(lingerTimer) | 1.300 | 2.275 |
| 팀파니 Lv5 | 지진지대 duration | ~3.0(초기값) | ~5.25(초기값) |
| 바이올린 Lv5 | 잔향 duration | 2.000 | 3.500 |
| 벨 Lv5 | 잔향 duration | 1.500 | 2.625 |
| 플루트 Lv2 | 소용돌이 유지시간 | 2.100 | 3.675 |

- [x] 5개 항목 전부 정확히 1.75배 확인. (팀파니는 `remainingDuration`이 매 프레임 실시간으로
      줄어드는 필드라 측정 시점에 따라 초기값보다 0.02~0.10 정도 작게 읽혔는데, 스폰 직후 값이
      정확히 3.000/5.250이었음을 별도로 확인 — 실시간 카운트다운이라는 설계상 정상 동작이지 버그
      아님)

### 회귀 확인

- [x] **데미지 값은 이번 변경과 무관**: 첼로 `damage`(10→10), 팀파니 지진지대 `tickDamage`
      (10→10) — 알레그로/페르마타 Lv0/Lv5 양쪽 다 동일. 코드상으로도 데미지 계산과 interval/duration
      계산이 완전히 분리된 변수라 구조적으로 안전.
- [x] **`HoldDurationSeconds`는 페르마타와 무관**: 페르마타 Lv5 활성 상태에서 홀드 노트를 스폰해도
      `HoldDurationSeconds`가 입력값(4.020) 그대로 유지됨을 확인 — 의도대로 절대 곱해지지 않음.
- [x] **크레센도(범위) 배율이 여전히 정상 동작**: 알레그로 Lv5 + 페르마타 Lv5 + 크레센도 Lv5를
      동시에 켠 상태에서 팀파니 Lv5 지진지대 하나를 만들어 세 값을 동시에 확인 — `radius`=1.500
      (크레센도만 반영, 1.0×1.5), `tickInterval`=0.350(알레그로만 반영, 0.5×0.7), `duration`≈5.25
      (페르마타만 반영, 3.0×1.75). 세 배율이 서로 다른 변수에 각각 곱해지며 서로 침범하지 않고
      독립적으로 정확히 동작함을 한 오브젝트에서 동시 확인.
- [x] **알레그로/페르마타 Lv0(미장착) 상태에서 기존과 완전히 동일**: 위 두 표의 "Lv0" 열이 전부 각
      악기 코드에 원래 있던 하드코딩 기본값(드럼 0.5/첼로 0.4/프렌치호른 0.2/팀파니 0.65·0.5/바이올린
      0.35·0.4/벨 0.3, 첼로 1.3/팀파니 3.0/바이올린 2.0/벨 1.5/플루트 2.1)과 정확히 일치 — 최소 회귀
      기준 충족.

**버그**: 발견되지 않았습니다. 알레그로/페르마타 둘 다, 7개 파일 전부 문서에 적힌 대로 정확히
동작하며, 이미 연동되어 있던 크레센도(범위)와도 서로 간섭 없이 함께 정상 동작합니다.
