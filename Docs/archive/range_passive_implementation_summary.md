# 공격 범위 시각화 + 크레센도(범위 증가) 패시브 연동 정리

실플레이 중 발견된 문제 3가지를 계기로, 드럼의 공격 범위 표시 버그를 고치고 그 과정에서 발견한
"범위 공격 증가" 패시브(크레센도)가 프로젝트 전체에서 아무 효과도 없던 문제를 10종 악기 전부에
연결했습니다. 두 차례 Unity MCP 실측 검증까지 전부 PASS로 완료됐습니다.

## 1. 발견 경위

플레이 중 다음 세 가지가 눈에 띄었습니다.

1. 드럼의 상시 "비트 오라" 공격 범위가 화면에 안 보여서 감으로 플레이해야 함.
2. 정박 타격 시 나가는 "비트 뱅" 충격파 모션 크기가 레벨이 올라도 항상 일정해 보임.
3. "범위 공격 증가" 카드(패시브)를 먹어도 체감상 아무 변화가 없음.

세 가지 모두 원인이 연결되어 있었습니다.

## 2. 근본 원인

- **오라 비주얼이 갱신 안 됨**: `DrumAuraController`의 오라 링이 생성 시점에 딱 한 번 고정 크기로
  그려지고, 이후 레벨업으로 실제 판정 반경이 커져도 비주얼은 그대로였습니다.
- **비트 뱅 충격파 스케일 계산이 부정확함**: `ShockwaveVisualEffect`가 `radius * 2f`라는 근사 배율을
  썼는데, 이 배율이 스프라이트(`CreateRingWithCore`)의 내부 픽셀 비율을 감안하지 않은 값이라 실제
  판정 범위보다 훨씬 작게(대략 0.3배) 그려지고 있었습니다. 레벨업으로 반경이 조금 커져도 화면상
  차이가 거의 안 보였던 것도 같은 원인입니다.
- **크레센도 패시브가 죽은 스탯이었음**: `PassiveStatManager.GetRangeMultiplier()` 계산 함수 자체는
  있었지만, 실제로 이 값을 곱해 쓰는 코드가 프로젝트 전체에 단 한 곳도 없었습니다. 카드 설명은
  "모든 공격 범위 +10%/Lv(최대 +50%)"인데, 소비하는 쪽이 없어 카드를 먹어도 수치 계산만 되고
  게임플레이에는 아무 영향이 없었습니다.

## 3. 해결 방법

### 3-1. 정확한 반경-비주얼 매칭 인프라

`ProceduralSpriteFactory.CreateUnitRing(innerRadius01, outerRadius01, color)`를 신설했습니다.
`scale=1`일 때 링 바깥쪽 끝이 정확히 "월드 유닛 반지름 1"이 되도록 픽셀 좌표계를 설계해서, 이후로는
`transform.localScale = Vector3.one * 실제반경`만 하면 항상 정확히 일치합니다. 기존
`CreateRingWithCore`(보스/엘리트 상자/보스 투사체/악기 아이템이 여전히 사용 중)는 장식용이라 정확한
반경 매칭이 필요 없어 그대로 뒀습니다.

이 인프라로 `ShockwaveVisualEffect`(비트 뱅 모션)를 다시 작성했고, `DrumAuraController`의 오라
링도 매 프레임 실제 판정 반경으로 갱신하도록 고쳤습니다.

### 3-2. 크레센도 패시브 연동

`CombatTargetingUtility.GetRangeMultiplier()` 헬퍼를 신설해 반복되는 null 체크를 없애고, 10종
악기 전부의 "사거리/반경" 계산식에 이 배율을 곱했습니다. 데미지 계산식은 전혀 건드리지 않았습니다.

| 악기 | 반영한 파라미터 | 반영 안 한 것(과 이유) |
|---|---|---|
| 드럼 | 오라 반경, 비트 뱅 반경 | - |
| 피아노 | 빔 최대 사거리(9f) | - |
| 벨 | 8방향 빔 사거리(2.5f×레벨) | - |
| 마림바 | 파동 최대 사거리(10f) | - |
| 글록켄슈필 | 스플래시 반경(0.6f+레벨) | 타겟팅(체력 최고 적 탐색)은 원래 거리 제한 없음 |
| 바이올린 | 궤도 칼날 반경(1.4f×레벨), 참격 사거리(6f), **Lv5 잔향 반경(0.6f)** | - |
| 프렌치호른 | 부채꼴 사거리(3.0f×레벨) | 부채꼴 각도(`halfAngleDeg`)는 범위가 아니라 별개 스탯 |
| 첼로 | 중력장 반경(1.8f×레벨) | - |
| 팀파니 | 캐논 반경(1.0f×레벨), **Lv5 지진지대 반경(1.0f)**, 융단폭격 스플래시(0.7f)+랜덤 오프셋(±1.0) | 아래 3-3 참고 |
| 플루트 | 흡입 반경(2.0f×레벨) | 당기는 힘 세기·지속시간은 범위가 아님 |

### 3-3. 팀파니 융단폭격 - "동일 배율" 결정

팀파니 홀드 중 발동하는 "융단폭격"은 지정 구역 주변 랜덤 오프셋(±1.0 정사각형)에 소형 착탄
(스플래시 반경 0.7)을 떨어뜨립니다. 고정 표적 하나를 기준으로 계산하면 명중 확률은 "스플래시 원
넓이 ÷ 오프셋 정사각형 넓이" 비율로 결정되어 약 38.5%입니다.

범위 배율을 적용할 때 스플래시와 오프셋 중 하나만 늘리면 이 비율이 깨집니다 — 스플래시만 늘리면
명중률이 급상승하고, 오프셋만 늘리면 반대로 급락합니다. 이미 `dps_balance_gap_analysis.md`에서
이 38.5% 명중률을 전제로 DPS 밸런스를 튜닝해뒀기 때문에, **스플래시와 오프셋에 정확히 같은 배율을
곱하기로 결정**했습니다(2026-08-06). 이 경우 수학적으로 명중 확률은 배율과 무관하게 그대로
유지되고, "커버하는 절대 면적"만 넓어집니다.

### 3-4. 잔류 장판류(바이올린 Lv5 잔향, 팀파니 Lv5 지진지대) 포함 결정

두 효과 모두 "범위 공격이 지나간 자리에 남는 잔류 효과"라는 성격이라, 처음엔 "범위 스탯" 대상인지
애매했습니다. "공격 범위에 따라 잔향이 남는 것이므로 포함하는 게 맞다"고 판단해 둘 다 범위 배율
적용 대상에 포함했습니다(2026-08-06).

## 4. 검증 결과 요약

두 차례에 걸쳐 Unity MCP로 실측 검증했고, **전부 PASS — 발견된 버그 없음**입니다. 상세 과정과
수치는 아래 archive 문서에 남아있습니다.

- `archive/drum_range_visualization_test_guide.md`: 드럼 오라/비트 뱅 비주얼-판정 반경 일치, 레벨별
  증가, 기존 `CreateRingWithCore` 사용처(보스/엘리트 상자/보스 투사체/악기 아이템) 무관함을 확인.
- `archive/instrument_range_passive_test_guide.md`: 나머지 9종 전부 Lv0/Lv5 배율이 정확히 1.5배로
  반영됨을 실측(피아노 9→13.5, 벨 2.5→3.75, 마림바 10→15, 글록켄슈필 0.6→0.9, 바이올린 1.4→2.1 +
  6→9 + 0.6→0.9, 프렌치호른 3.0→4.5(각도 60°는 불변), 첼로 1.8→2.7, 팀파니 1.0→1.5 + 0.7→1.05 +
  1.0→1.5, 플루트 2.0→3.0). 팀파니 융단폭격 명중률은 40회 반복 착탄 기준 크레센도 미보유 25.0%,
  만렙 37.5% — 이론치(38.5%) 근방에서 통계적으로 유의미한 차이 없음을 확인. 데미지 수치는 9종
  전부 배율과 무관하게 그대로임도 함께 확인.

검증 과정에서 나온 특기할 점(코드 버그 아님, 테스트 방법론 기록):
- Unity 에디터가 OS 포커스를 잃으면 Play Mode `Update()` 틱이 멈추는 현상 — `manage_editor(pause)`
  + `EditorApplication.Step()` 수동 프레임 진행으로 우회.
- 자동 타겟팅(`GetNearestEnemy` 등)을 쓰는 이펙트를 테스트할 때, 백그라운드에서 실제로 스폰되는
  잡몹이 테스트용 고정 표적보다 가까우면 타겟팅이 엉뚱한 몹으로 튈 수 있음 — 테스트 전
  `EnemySpawner`를 비활성화하거나 `activeEnemies`를 비워야 함.

## 5. 남은 고려 사항

- **DPS 밸런스는 "크레센도 미보유" 기준으로만 검증되어 있습니다**: 사거리가 넓어지면 다수 적
  상황에서 명중 횟수가 늘어 체감 DPS가 높아질 수 있습니다. 크레센도를 적극적으로 찍는 빌드의 종합
  밸런스는 별도 확인이 필요할 수 있습니다.
- **드럼 외 9종은 여전히 상시 범위 인디케이터가 없습니다**: 이번엔 드럼처럼 "판정 성공과 무관하게
  항상 켜져 있는" 공격에만 상시 링 비주얼을 추가했습니다. 나머지 9종은 투사체/임팩트 이펙트 자체가
  발동 지점을 보여주긴 하지만, "여기까지가 사거리다"라는 상시 표시는 없습니다. 필요하면 별도 라운드로
  검토할 수 있습니다.
