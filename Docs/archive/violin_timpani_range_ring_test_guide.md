# 바이올린·팀파니 범위 인디케이터 추가 - 검증 가이드

이 문서는 **Unity MCP가 연결된 별도 Claude Code 세션**에서 이번 작업을 실측 검증할 때 참고하는
절차서입니다. 아직 커밋하지 않은 상태입니다.

검증이 끝나면 이 파일 하단에 결과를 추가로 append해주세요.

## 0. 무엇을 고쳤나

프렌치호른·첼로·플루트에 이어, 지속 유지형 공격을 가진 나머지 두 악기(바이올린/팀파니)에도 범위
인디케이터를 추가했습니다. 둘 다 드럼과 동일한 `CreateUnitRing(0.985f, 1f, ...)` 아주 얇은 테두리
링을 사용합니다.

- **바이올린**: 홀드 중 회전하는 칼날의 궤도 반경(`radius`)을 표시하는 링을 추가했습니다. 이
  컴포넌트의 `transform.localScale`은 항상 1로 고정(칼날은 각도만 바꿔 배치되는 구조)이라, 프렌치호른/
  첼로/플루트 때와 달리 부모 스케일을 상쇄하는 계산 없이 `radius`를 그대로 링의 `localScale`에
  곱했습니다. 링은 자식 오브젝트라 매 프레임 `OnHoldTick`에서 갱신되는 플레이어 위치를 자동으로
  따라갑니다.
- **팀파니**: 홀드 유지 중 "융단폭격"이 착탄할 수 있는 구역(오프셋 ±1.0×크레센도 배율의 정사각형
  범위, `OnHoldTick`의 `Random.Range(-1.0f, 1.0f) * rangeMultiplier`)을 표시하는 링을 추가했습니다.
  실제로는 정사각형 범위지만, 프렌치호른의 부채꼴 근사와 같은 방식으로 반지름 1.0×배율의 원으로
  근사했습니다. `targetPos`(홀드 시작 시점의 최근접 적 위치)에 고정되며, 이 컴포넌트의 GameObject
  transform은 별도 용도가 없어 자식 오브젝트의 월드 위치를 `targetPos`로 직접 지정했습니다.

두 경우 모두 자식 오브젝트라 부모가 `Destroy()`될 때(홀드 종료) 별도 처리 없이 함께 정리됩니다.

## 1. 사전 준비

1. `refresh_unity(mode=force, compile=request)` → `read_console`로 컴파일 에러 확인.
2. 두 악기 모두 홀드 판정에 성공시켜야 확인 가능합니다. 크레센도(범위 증가) 패시브를 Lv5로 세팅해두면
   반경 변화까지 함께 확인할 수 있습니다.

## 2. 검증 항목

- [ ] 바이올린 홀드 중 테두리 링의 실제 월드 반경이 `radius` 필드값과 정확히 일치하는지
- [ ] 바이올린: 플레이어가 이동하면 링도 칼날과 함께 정확히 따라가는지
- [ ] 팀파니 홀드 중 테두리 링의 실제 월드 반경이 `1.0 × GetRangeMultiplier()`와 정확히 일치하는지
- [ ] 팀파니: 링이 `targetPos`(홀드 시작 시점 위치)에 고정되어 있고, 플레이어가 이동해도 안 따라가는지
- [ ] 크레센도 Lv0→Lv5로 반경이 커질 때 두 링 모두 정확히 함께 커지는지
- [ ] 두 악기 모두 링 두께가 드럼 오라 링과 동일하게 아주 얇게(바깥 반경 대비 1.5%) 보이는지
- [ ] **회귀**: 데미지/판정 로직(칼날 재타격, 융단폭격 착탄, 레가토 추가 발사 등)은 이번 변경과
      무관하게 그대로인지
- [ ] **회귀**: 홀드 종료 시 두 링(자식 오브젝트)도 함께 정상 파괴되는지
- [ ] **회귀**: 레가토(추가 칼날/추가 캐논)와 링이 서로 간섭 없이 함께 정상 동작하는지

## 4. 검증 결과

**검증 일시**: 2026-08-07 / Unity MCP 연결 세션, Play Mode에서 `ViolinOrbitEffect`/`TimpaniBombardmentEffect`의
실제 `Init`/`OnHoldTick`/`OnHoldReleased`를 리플렉션으로 직접 호출해 측정.

### 0. 사전 준비
- `refresh_unity(force, compile=request)` → 컴파일 성공, 에러/경고 0건.
- Play Mode 진입 성공.

### 1. 바이올린 링 반경 정확도
Lv1, 크레센도 Lv0(rangeMultiplier=1.0) 기준: `radius` 필드 = 1.40000, 링의 `lossyScale.x` = 1.40000 —
정확히 일치. (`transform.localScale`이 항상 1로 고정되어 있음도 함께 확인.)

### 2. 바이올린 추종
플레이어를 `(0,0,0) → (3,2,0)`으로 이동시키고 `OnHoldTick`을 호출한 결과, 바이올린 본체와 링(자식,
로컬 오프셋 0) 모두 정확히 플레이어를 따라 이동함을 확인. Lv1+크레센도Lv5+레가토 extraProjectiles=3
조합(칼날 5개)에서도 `OnHoldTick` 호출 후 5개 칼날 전부 중심으로부터 정확히 `radius`(2.1) 거리에
위치함을 확인 — 늘어난 칼날도 기존 궤도 로직을 정상적으로 공유.

### 3. 팀파니 링 반경 정확도
Lv1, 크레센도 Lv5(rangeMultiplier=1.5) 기준: 링의 `lossyScale.x` = 1.50000 (기대값 `1.0 × 1.5 = 1.5`)로
정확히 일치. 레가토 extraProjectiles=3을 줘도 반경은 동일하게 1.5 — 레가토(추가 캐논 발사 개수)와
범위 인디케이터가 서로 간섭 없음을 확인(§9와 연결).

### 4. 팀파니 고정 위치
링의 월드 위치가 `Init` 시점의 `targetPos`(예: `(5,5,0)`, `(-3,2,0)`)와 정확히 일치. 플레이어를 큰 폭
(`+20,-8,0`)으로 이동시키고 `OnHoldTick`을 두 차례(폭격 주기 경과 포함) 호출해도 팀파니 본체의
`transform.position`과 링의 월드 위치 모두 완전히 불변임을 확인 — 팀파니는 바이올린과 달리 자기
transform을 플레이어 위치로 갱신하는 코드가 없어 구조적으로도 보장됨.

### 5. 크레센도 Lv0→Lv5 확대
두 악기 모두 반경이 정확히 배율만큼 커짐을 위 1번/3번 항목에서 함께 확인(바이올린 1.4→2.1, 팀파니
1.0→1.5).

### 6. 링 두께
두 악기 모두 기존 프렌치호른/첼로/플루트/드럼과 동일한 `CreateUnitRing(0.985f, 1f, ...)` 호출 — 구조적으로
동일한 두께 비율(1.5%). 스크린샷에서도 얇은 테두리로 정상 렌더링 확인(아래).

**스크린샷**: 마젠타 링이 바이올린 회전 칼날(다이아몬드)의 궤도 반경을 정확히 감싸고, 시안 링이 팀파니
목표 지점에 고정되어 표시됨. `Assets/Screenshots/screenshot-20260807-225057.png`에 저장.

### 7. 회귀 — 데미지/판정 로직 불변
`git diff` 확인 결과 두 파일 모두 링 생성 코드가 각 `Init` 끝에 순수 추가된 블록뿐이며, 칼날 재타격
(`TickDamage`), 융단폭격 착탄(`OnHoldTick`의 `SpawnImpact` 호출), 레가토 추가 발사 로직 등 기존 판정
코드는 삭제/수정된 라인이 전혀 없음(diff에 `-` 라인 없음, 전부 `+` 추가).

### 8. 회귀 — 홀드 종료 시 링(자식)도 함께 파괴
바이올린/팀파니 각각 `OnHoldReleased(true)` → `Destroy(gameObject)` 호출 후 에디터 프레임을 진행시켜
(`EditorApplication.Step()`), 부모와 자식(`ViolinRangeRing`/`TimpaniZoneRing`) 모두 씬에서 완전히
사라짐을 확인. 같은 시점에 살아있던 다른 테스트 인스턴스들의 링은 정상적으로 남아있어, 정확히 해당
인스턴스의 자식만 함께 파괴되었음을 교차 확인.

### 9. 회귀 — 레가토(추가 칼날/추가 캐논)와 링 간섭 없음
- 바이올린: extraProjectiles=3으로 칼날이 2→5개로 늘어나도 링 반경(2.1)은 전혀 영향받지 않음, 5개
  칼날 모두 정상적으로 `radius` 거리에서 궤도 회전.
- 팀파니: extraProjectiles=3으로 홀드 시작 시 착탄이 1→4개로 늘어나도 링 반경(1.5)과 위치(`targetPos`)는
  전혀 영향받지 않음.

두 경우 모두 레가토 로직(칼날/캐논 개수)과 범위 인디케이터(링) 코드가 완전히 독립적으로 동작함을 확인.

### 종합 결과
검증 가이드의 9개 항목 모두 통과. 컴파일 에러/경고 없음(무관한 네트워크 릴레이 경고 1건만 존재).
반경 정확도, 추종/고정 위치, 크레센도 스케일링, 링 두께, 데미지/판정 로직 무변경, 파괴 시 자식 동반
파괴, 레가토와의 무간섭까지 전부 확인됨. 테스트용으로 생성한 임시 GameObject는 모두 정리 완료.
