# DPS 밸런스 보정 실측 검증 결과

`Docs/dps_balance_test_guide.md`와 `Docs/dps_balance_gap_analysis.md`에 따라 `InstrumentDamageTable.cs` +
`RhythmAttackManager.cs`의 악기별 DPS 보정 배율이 실제로 목표 DPS(`game_balance_design.md` 5번 항목)에
얼마나 근접하는지 Unity MCP로 실측했습니다.

**종합 결과: 10종 중 6종(드럼/피아노/마림바/프렌치호른/첼로 + 무피해 플루트)은 목표 범위(0.7~1.3배) 안에
들어와 합격입니다. 그러나 4종(벨/글록켄슈필 Lv5/바이올린 Lv5/팀파니 Lv5)에서 목표를 1.7~9배 초과하는
심각한 격차가 발견됐습니다 — 특히 벨은 단순 배율 문제가 아니라 "8방향 발사가 전부 타겟 위치에서
시작"하는 구조적 문제로, 배율만 낮추면 다수 적 대상 광역 피해가 무의미해질 수 있어 설계 검토가
필요합니다.** 팀파니 Lv1은 반대로 목표에 약간 못 미칩니다(0.55배, 융단폭격 랜덤 오프셋으로 인한 명중률
저하가 원인으로 추정).

## 0. 측정 방법론

### 0-1. 기본 설정
- `refresh_unity(mode=force, compile=request)` → 컴파일 에러 없음(MCP 플러그인 자체 WebSocket 경고
  1건만 존재, 프로젝트 코드와 무관).
- Play Mode 진입, `Time.timeScale = 0f` 고정(1~4단계에서 정립된 결정론적 검증 방법론 재사용).
- **M_rhythm=1.0 강제**: `RhythmManager.RhythmSuccessRate01`은 private setter라 리플렉션으로
  `<RhythmSuccessRate01>k__BackingField`에 `1/3f`를 직접 주입해 `GetRhythmDamageMultiplier() = 0.5 +
  1.5×(1/3) = 1.0`을 만들었습니다(가이드 및 gap_analysis가 목표 DPS를 "M_rhythm=1.0, M_stat=1.0"
  조건으로 정의했기 때문 — 실제 `HandleRhythmHit()`을 리듬 판정 흐름 없이 직접 호출하면
  `RhythmSuccessRate01`이 초기값 0에 머물러 M_rhythm이 0.5로 고정되므로 반드시 필요한 보정입니다).
- **M_stat=1.0**: `PassiveStatManager`에 시포르찬도 패시브를 전혀 획득하지 않은 새 게임 상태 그대로라
  `GetDamageMultiplier()`가 기본값 1.0을 반환함을 확인 — 별도 조작 불필요.
- **측정 대상 악기 1개만 장착**: `InstrumentManager.AcquiredInstruments`(실제 리스트 참조를 그대로
  반환)를 직접 `Clear()` 후 `new InstrumentInfo(type, level)` 1개만 `Add()` — 가이드가 요구한
  "다른 악기 전부 미장착" 조건을 만족.
- **더미**: `EnemyMonster`를 `Initialize(null, null, Color.white, 999999 또는 2,000,000)`로 생성,
  플레이어 위치 + `Vector3.up * 0.5f`에 고정 배치. 넉백/밀쳐냄 효과가 있는 악기(드럼, 벨 다음 hit 등)는
  **매 타격 직전에 더미 위치를 고정 위치로 리셋**해, 가이드가 명시한 "더미가 항상 사거리 안에 있다"는
  가정을 유지했습니다(리셋하지 않으면 자체 넉백으로 사거리 밖으로 밀려나 후속 타격이 누락되는 테스트
  아티팩트가 발생함을 확인 — 실제로 첫 시도에서 드럼 Lv1의 4번째 타격이 이 문제로 누락됐었음).
- **프렌치호른 전용 보정**: `FrenchHornConeEffect`는 플레이어의 실제 바라보는 방향(`facingDirection`,
  기본값 Down)과 적의 상대각을 계산하므로, 더미를 "Up" 방향에 고정 배치한 기본 설정과 충돌해 최초
  측정에서 데미지 0이 나왔습니다. `PlayerController.facingDirection`을 리플렉션으로 `Up`으로 맞춘 뒤
  재측정해 해결(테스트 스크립트 설정 문제였고, 게임 로직 버그 아님).

### 0-2. `Time.timeScale=0`에서 지연 로직 강제 처리 (3~4단계 기법 재사용/확장)
탭 5종의 투사체(`PiercingBeamProjectile`)·범위 임팩트(`AreaImpactEffect`)·유도탄
(`HomingShrapnelProjectile`)은 전부 `Time.deltaTime`을 내부에서 직접 읽어 이동/딜레이를 처리하므로,
`timeScale=0`에서는 자연 진행이 불가능합니다. 아래 기법으로 결정론적으로 강제 판정했습니다:
- `PiercingBeamProjectile`: 스폰 직후 `transform.position`을 더미 위치로 강제 이동시킨 뒤, private
  `CheckHits()`를 리플렉션으로 즉시 1회 호출(실제 이동 애니메이션 없이 "명중 판정"만 즉시 실행).
- `AreaImpactEffect`: private `Impact()`를 리플렉션으로 직접 호출해 낙하 딜레이를 건너뛰고 즉시 착탄
  처리(스플래시 판정에 필요한 거리 계산은 실제 코드 그대로 실행되므로, 팀파니 융단폭격의 랜덤 오프셋
  명중/실패 여부도 실제 확률 그대로 반영됨).
- `HomingShrapnelProjectile`: `transform.position`을 타겟 위치와 정확히 일치시켜(`step.magnitude(0) >=
  dist(0)` 조건 충족) `Update()`를 1회 호출 — 유도 이동 없이 도착 판정만 즉시 실행.
- `LingeringZoneEffect`(벨/바이올린/팀파니 Lv5 잔류 장판): 랜덤 요소가 전혀 없는 결정론적 카운터라,
  `Update()`를 반복 호출하는 대신 `floor(remainingDuration / tickInterval)`로 총 틱 수를 계산해
  `tickDamage × 틱수`를 직접 적용(단, 팀파니 지진지대는 스폰 위치가 착탄 지점별로 달라 더미와의 거리
  조건을 먼저 확인한 뒤에만 적용).

### 0-3. 홀드 4종은 실제 틱 루프 그대로 사용
`ViolinOrbitEffect`/`CelloGravityFieldEffect`/`FrenchHornConeEffect`/`TimpaniBombardmentEffect`의
`OnHoldTick(float deltaTime)`은 `Time.deltaTime`이 아니라 **파라미터로 받은 deltaTime**만 사용하므로,
`HoldEffectCoordinator.Tick(lane, 0.05f)`을 가이드가 제시한 대로 실제 홀드 길이만큼 반복 호출하는 것만으로
완전히 결정론적입니다(강제 주입 불필요). `HandleRhythmHit()`을 그대로 호출해 `BeginHold`를 트리거하는
가이드의 대체 방법을 사용해 실제 데미지 계산 공식과 100% 동일한 값을 얻었습니다.

### 0-4. 알려진 측정 한계 (가이드 4번 섹션과 동일한 취지)
- **첼로 Lv4/5 "잔류시간"(release 이후 자체 Update() 지속)은 측정에서 제외**했습니다 — 이 로직은
  `Time.deltaTime`을 내부에서 직접 읽는 `CelloGravityFieldEffect.Update()`가 담당하는데,
  `HoldEffectCoordinator`가 관리하지 않는 "홀드 종료 후 자체 생존 오브젝트"라 3~4단계식 필드 주입
  기법을 그대로 적용하기 애매합니다(주기적 반복 홀드 사이클 측정 흐름과 맞지 않음). 따라서 **첼로 Lv4/5
  실측치는 실제보다 낮게 측정된 하한값**이며, 특히 Lv5(115.2, 목표比 0.77)는 잔류시간을 포함하면 목표에
  더 가까워질 가능성이 높습니다.
- **팀파니 융단폭격의 랜덤 오프셋**(±1.0 범위 정사각형 안에서 스플래시 반경 0.7로 판정)은 강제로 값을
  주입하지 않고 실제 `Random.Range` 그대로 실행했습니다 — 즉 팀파니 결과는 "그 순간의 RNG 표본 1개"이며
  재측정 시 값이 다소 달라질 수 있습니다(단일 고정 표적 기준 기대 명중률 ≈ 38.5%로 추정).
- **글록켄슈필 Lv5 유도 파편**은 "다른 적"이 있어야 발사되므로, 주 타겟(HP 2,000,000)과 별도로 5유닛
  떨어진 보조 더미(HP 999,999)를 추가 배치했습니다. 두 더미의 총 피해량을 합산해 DPS를 계산했습니다
  (실제 게임에서도 유도 파편은 별도의 적을 타격하는 광역 피해이므로, 총 딜량 관점에서는 합산이 타당하다고
  판단했습니다).

## 2. 심각한 초과 항목 상세 원인 분석

### 2-1. 벨 — 구조적 문제 (배율만으로 해결 불가, 설계 검토 필요) 🔴
`ExecuteBell()`은 `center = 가장 가까운 적의 현재 위치`로 설정한 뒤 그 지점에서 8방향으로 빔을
**동시에 스폰**합니다(`InstrumentAttackDispatcher.cs:157-173`). 즉 "가장 가까운 적"은 자신이 서 있는
바로 그 자리에서 발사되는 8개 빔 전부와 거리 0으로 겹쳐 있어, **정상적인 게임 플레이에서도 타겟 1마리가
8발(Lv4+는 2연속 발사로 16발) 전부를 그대로 맞습니다.** gap_analysis의 이론 추정치는 "8방향 중 1발만
맞는다"는 보수적 가정을 깔고 배율을 역산했지만, 실제 코드 동작은 그 가정과 다릅니다 — 배율이 잘못된 게
아니라 **원본 이론 추정의 전제 자체가 실제 구현과 어긋났습니다.**
- 단순히 배율을 낮추면(예: Lv1 75.0→9.3배) 단일 타겟 DPS는 맞출 수 있지만, 여러 적이 흩어져 있을 때
  "8방향 중 1~2발만 맞는" 실제 광역 상황에서는 데미지가 목표치의 1/8로 떨어져 벨의 광역 소탕력이
  사실상 무력화됩니다.
- **권장 방향(설계 판단 필요)**: (a) 발사 시작점을 타겟이 아니라 플레이어 위치로 바꿔 "8방향 전부 명중"
  상황 자체를 없애거나, (b) 같은 프레임에 동일 타겟을 맞춘 빔은 1발로 취급(`hitEnemies`를 빔 간에
  공유)하거나, (c) 배율을 대폭 낮추고 "단일 타겟 집중 처형기"로 컨셉을 변경. 어느 쪽이든 코드 수정이
  필요해 이번 라운드에서 직접 고치지 않았습니다.
- 참고로 보스전에도 그대로 적용됩니다 — 보스가 "가장 가까운 적"으로 선택되면 보스도 8~16발을 동시에
  맞아, 벨 장착 시 보스전 난이도가 설계 의도보다 크게 낮아질 수 있습니다.

### 2-2. 글록켄슈필 Lv5 — 유도 파편이 이론 추정에서 누락됨 🟠
Lv5의 "2차 유도 파편"(`HomingShrapnelProjectile`)은 조건 없이 매 타격마다 발사되어 **주 타겟과 별개인
2번째 적에게 동일한 `scaledDamage`를 그대로 꽂습니다.** 실측 결과 주 타격(스플래시+버스트) 자체는
1501(목표 근사치 수준)로 비교적 정상이었지만, 유도 파편이 추가로 1027을 더해 총 2528(비율 1.70)까지
끌어올렸습니다. gap_analysis §2-3의 가정 목록에는 유도 파편 관련 언급이 전혀 없어, 배율 역산 시
이 몫이 처음부터 빠진 것으로 보입니다.
- **권장 배율**: 목표 총딜량(1484.55) ÷ 실측(2528) × 기존 배율(15.2) ≈ **8.9**

### 2-3. 바이올린 Lv5 — 잔향 장판 개수가 과다 🟠
릴리즈 참격 1회당 참격 3발 × 참격당 잔향 3개 = **9개의 `LingeringZoneEffect`가 동시에 생성**되고,
각 장판이 5틱(`duration 2s / interval 0.4s`)씩 피해를 줘 잔향만으로 1620 데미지(목표 총딜량의
109%)가 나왔습니다. 칼날+참격 자체 데미지(864, 목표比 0.58배로 오히려 살짝 부족)에 잔향이 더해지며
총합이 목표의 1.82배까지 초과됩니다.
- **권장 배율**: 목표(1484.55) ÷ 실측(2700) × 기존 배율(9.0) ≈ **4.9** (단, 이렇게 낮추면 잔향 없는
  Lv1~4 대비 상대적으로 너무 약해질 수 있어, 배율 대신 잔향 개수(9개→3개) 또는 지속시간을 줄이는
  방향도 함께 검토를 권장합니다)

### 2-4. 팀파니 Lv5 — 착탄마다 지진지대가 중첩 생성되어 기하급수적으로 누적 🔴
Lv5는 **모든 착탄**(홀드 시작 즉시 캐논 1회 + 융단폭격 틱마다, 약 0.43초 간격)마다 3초짜리 지진지대를
새로 생성합니다. 지대의 수명(3초)이 생성 간격(0.43초)보다 훨씬 길어 **다수의 지진지대가 동시에
중첩 잔존**하고, 실측 2회 홀드에서만 지진지대 피해가 3780(목표 총딜량의 254%)에 달했습니다. 이는
홀드를 더 길게/자주 유지할수록 계속 심해지는 구조라, 실제 플레이(더 긴 지속 홀드)에서는 격차가 더 벌어질
수 있습니다.
- **권장 배율**: 목표(1484.55) ÷ 실측(4562) × 기존 배율(23.1) ≈ **7.5** (단, 위 벨/바이올린과 마찬가지로
  배율만 낮추면 지진지대 자체의 존재 의미가 옅어지므로, 지대 생성 빈도를 착탄마다가 아니라 "일정 쿨다운
  이상 지난 착탄에서만"으로 제한하는 설계 변경도 함께 고려할 만합니다)

### 2-5. 팀파니 Lv1 — 융단폭격 랜덤 오프셋으로 인한 명중률 저하 (경미, 재검토 권장)
Lv1~2는 융단폭격 틱마다 ±1.0 범위 랜덤 오프셋 지점에 반경 0.7 스플래시를 떨어뜨리는데, 단일 고정
표적 기준 기대 명중률이 약 38.5%에 불과해(원의 넓이 π×0.7²=1.539 ÷ 정사각형 넓이 2×2=4) 융단폭격
몫의 실질 기여가 이론치보다 낮습니다. 초기 캐논 1회는 항상 명중하므로 격차가 벨/팀파니Lv5만큼 크지는
않지만(0.55배), 여러 표적이 흩어진 실제 전투에서는 이 랜덤 오프셋이 오히려 "여러 마리 동시 타격" 기회로
작용해 실제 체감 DPS는 단일 더미 측정치보다 높을 가능성이 있습니다 — 순수 배율 문제라기보다 "단일
표적 측정 방법론 자체의 한계"에 가깝다고 판단해 심각도는 낮게 분류했습니다.

## 4. 종합 권장 사항

1. **벨은 배율 조정 이전에 설계 검토가 우선입니다** (2-1 참고) — 다른 3개 항목과 달리 단순 역산 배율
   축소로는 근본 해결이 안 됩니다.
2. 글록켄슈필 Lv5(→8.9)/바이올린 Lv5(→4.9)/팀파니 Lv5(→7.5) 배율 재계산 값을 제시했습니다. 다만
   바이올린·팀파니는 배율 축소가 Lv5 전용 효과(잔향/지진지대)의 존재감을 사실상 없애버릴 수 있어,
   "발동 개수/빈도 제한" 같은 설계적 대안도 함께 검토를 권장합니다.
3. 팀파니 Lv2~4, 벨 Lv2~4, 글록켄슈필 Lv2~4, 바이올린 Lv2~4는 이번 라운드에서 측정하지 않았습니다
   (가이드 권장에 따라 Lv1/Lv5만 우선 측정) — 위 배율 재조정이 반영되면 중간 레벨도 보간이 맞는지
   추가 확인이 필요합니다.
4. Lv1~4 전 악기는 안정적이므로, 이번 라운드는 **"Lv5 전용 추가 기믹(잔향/지대/파편/2연속 등)이 배율
   역산 당시 과소평가됐다"는 공통 패턴**으로 요약할 수 있습니다. 다음 배율 재계산 시 Lv5 전용 부가효과의
   기여분을 별도 항목으로 분리해 계산하면 이런 격차를 방지하기 쉬울 것으로 보입니다.

기존 `RhythmAttackManager.HandleRhythmHit()`의 범용 투사체 폴백 로직(도달 불가능한 죽은 코드)에 대한
3단계 권장 사항은 이번 라운드와 무관하게 여전히 유효합니다.
