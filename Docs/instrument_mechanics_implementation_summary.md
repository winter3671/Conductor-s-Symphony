# 10종 악기별 공격 메커니즘 구현 정리

`10종 악기별 공격 메커니즘 기획서.docx`(메커니즘 기획서, 이하 "메커니즘 doc")와 `game_balance_design.docx`
(밸런스 기획서, 이하 "밸런스 doc") 두 문서에 걸쳐 정의된 10종 악기(드럼/피아노/바이올린/플루트/
프렌치호른/글록켄슈필/첼로/팀파니/마림바/벨)의 공격 메커니즘 구현이 3단계(1단계: 탭 4종, 2단계: 홀드
4종, 3단계: 드럼/플루트)에 걸쳐 전부 완료되었습니다. 이 문서는 두 기획서 내용과 실제 구현을 매핑하고,
기획서와 달라진 부분을 명확히 정리한 기록입니다.

**중요**: 실제 구현 작업(1~3단계)은 메커니즘 doc만 참고하며 진행되었고, 밸런스 doc 5번 항목("10종 전체
악기 5단계 레벨업 성장표 & Target DPS")에 정의된 악기별 구체적인 레벨 1~5 성장 내용은 교차 확인하지
못한 채 별도로 임의 수치를 사용했습니다. 이번에 두 문서를 함께 재검토하면서 발견된 차이점은 4번 섹션에
정리했고, **4단계 작업으로 그 차이의 대부분(레벨별 수치 곡선 + Lv4~5 부가 효과)을 실제로 반영했습니다.**
4번 섹션은 이제 "발견된 차이"가 아니라 "4단계에서 반영을 완료한 항목"과 "여전히 남아있는 항목"을
구분해 정리한 최신 상태입니다.

각 단계의 실측 검증 과정과 발견된 버그는 `archive/instrument_mechanics_phase1_test_result.md` /
`archive/..._phase2_test_result.md` / `archive/..._phase3_test_result.md`(과거 테스트 가이드/결과 모음
`Docs/archive/` 폴더로 이동됨) / `instrument_mechanics_phase4_test_result.md`에 남아있습니다. 4단계도
**Unity MCP 실측 검증까지 전부 PASS로 완료**됐습니다 — 6번 섹션 참고. 이 문서는 "최종적으로 무엇이
어떻게 구현되었는가"만 정리한 요약본입니다.

## 1. 전체 구조

모든 악기 공격은 판정 성공 이벤트(`RhythmManager.OnHitSuccessEvent`)를 `RhythmAttackManager.HandleRhythmHit()`가
받아서 처리합니다. 악기는 노트 입력 방식에 따라 두 그룹으로 나뉩니다.

- **탭(Tap) 기반 5종** — 피아노, 벨, 마림바, 글록켄슈필, 드럼. 판정 성공 즉시 1회성 공격이 발동합니다.
  `InstrumentAttackDispatcher.IsImplemented()` / `Execute()`가 담당합니다.
- **홀드(Hold) 기반 5종** — 바이올린, 프렌치호른, 첼로, 팀파니, 플루트. 판정 성공 시점이 홀드 "시작"이고,
  이후 키를 누르고 있는 동안 매 프레임 유지 효과가, 떼는 순간 해제 효과가 발동합니다.
  `InstrumentAttackDispatcher.IsHoldImplemented()` / `HoldEffectCoordinator`(레인별 지속 이펙트 관리)가
  담당합니다.

드럼만 예외적으로 위 두 파이프라인과 완전히 별개인 **판정과 무관한 상시 효과**(비트 오라)를 하나 더
가지고 있으며, 이는 `RhythmAttackManager.UpdateDrumAura()`가 매 프레임 독립적으로 처리합니다.

딜량 계산 자체(기본 DPS × M_rhythm × M_stat, 8종 패시브 스탯)는 밸런스 doc 1번·4번 항목을 그대로
따르고 있으며 이 부분은 이미 정확히 반영되어 있습니다(`RhythmAttackManager.HandleRhythmHit()`,
`PassiveStatManager`). 이번에 누락이 확인된 것은 밸런스 doc 5번 항목(악기별 5단계 성장표)입니다.

주요 공용 부품:
- `CombatTargetingUtility` — 가장 가까운 적 / 체력 최고 적 탐색
- `PiercingBeamProjectile` — 직선 관통 투사체(피아노/벨/마림바/바이올린 참격이 공유)
- `AreaImpactEffect` — 지연 낙하 광역 피해(글록켄슈필/팀파니가 공유)
- `IHoldAttackEffect` + `HoldEffectCoordinator` — 홀드 5종의 시작/유지/해제 생명주기 관리

## 2. 악기별 구현 내역

### 드럼 (Drums)
- **기획서**: 플레이어 중심 360°. 상시 "비트 오라"(근접 적에게 소량 지속 타격) + 정박(1,5,9,13) 타격 시
  "비트 뱅"(장판 팽창 + 전방위 넉백).
- **구현**: 두 효과 모두 그대로 구현.
  - 비트 오라: `RhythmAttackManager.UpdateDrumAura()`가 매 프레임 "드럼이 언락된 슬롯에 장착되어
    있는가"만 확인 — 판정 성공 여부와 완전히 무관. 0.5초 간격으로 반경(1.6 + 0.1×(Lv-1)) 내 적에게
    데미지 `max(1, round(1×M_stat))`을 가함(M_rhythm 미반영 — 아래 3번 참고).
  - 비트 뱅: `ExecuteDrums()`가 판정 성공 시 반경(Lv2+ +20%, 1회성) 내 적에게 표준 딜량 공식 그대로
    데미지(Lv2+ +20%) + 넉백(Lv3+ 2배)을 가하고 확장 링 이펙트를 재생.
- **[4단계 추가]** Lv3+: 맞은 적에게 0.5초간 50% 한시적 감속(`ApplyTemporarySlow`) 적용. Lv5: 비트 뱅이
  2회 연속 중첩 발동. Lv4+: 비트 오라 데미지도 `auraLevelMultiplier`로 +50% 반영(`RhythmAttackManager.
  UpdateDrumAura()`) — 문서 작성 당시 누락으로 "4단계 대상 아님"이라 잘못 기록했던 항목인데, 실제
  코드에는 이미 반영되어 있었고 4단계 실측 검증(PASS)에서 확인됐습니다.

### 피아노 (Piano)
- **기획서**: 가장 가까운 적 방향 관통 레이저. 14마디 6연타 성공 시 "건반 폭포"(3발 부채꼴 추가 발사).
- **구현**: `ExecutePiano()`. 관통 Lv1-2=2 / Lv3+=4. 발사 수 Lv1-3=1발 / Lv4+=2발. 전역 콤보가 6의
  배수일 때(Lv5) ±12° 부채꼴로 3발 추가.
- **[4단계 추가]** Lv2+: 데미지 +25%.

### 바이올린 (Violin)
- **기획서**: 13칸 롱노트. 홀드 중 플레이어 둘레 회전 활 칼날, 릴리즈 시 이동 방향 부채꼴 참격.
- **구현**: `ViolinOrbitEffect`. 홀드 중 칼날 2개(Lv3+ 3개)가 반경(Lv2+ +20%)에서 회전하며 같은
  적을 0.35초 쿨다운으로 지속 타격. 릴리즈 시 이동 방향 기준 3발(관통 3/5, 스프레드 14°) 참격.
- **[4단계 추가]** Lv2+: 회전 속도 +30%. Lv4+: 참격 발수 대신 "크기" +50%로 변경(밸런스 doc 표현에 맞춤 —
  이전엔 Lv4에서 발수를 5발로 늘렸었는데 doc은 "발수"가 아니라 "크기"를 요구해 정정). Lv5: 참격이 지나간
  자리에 `LingeringZoneEffect` 3개가 생성되어 2초간 지속 타격("검기 잔향").

### 플루트 (Flute)
- **기획서**: 2~4칸 숏 홀드. 릴리즈 시 "플레이어가 지나간 자리"에 미니 소용돌이 생성, 주변 적을
  끌어당김(순수 CC, 다른 광역 공격과 연계).
- **구현**: `FluteVortexHoldEffect` + `FluteVortexEffect`. 3칸 홀드로 근사. 홀드 유지 중에는 아무 효과도
  없고(의도된 단순화), 릴리즈 시에만 소용돌이 발동. **피해 없음** — 기획서의 "순수 CC" 의도를 그대로 반영.
- **[4단계 추가]** Lv2+: 유지시간 +40%(1회성). Lv3+: 흡입 범위·당기는 힘 각각 +50%(1회성). Lv4+: 동시
  유지 가능 소용돌이 2개까지(3개째 생성 시 가장 오래된 것 자동 정리, `activeVortices` 정적 리스트로
  관리). Lv5: 소멸 시 범위 내 적을 바깥으로 밀어내는 무피해 "바람 파편" 폭발.

### 프렌치호른 (French Horn)
- **기획서**: 6칸 스웰 롱노트. 홀드 중 이동 방향 전방 부채꼴에 지속 충격파 + 밀쳐냄(넉백).
- **구현**: `FrenchHornConeEffect`. 사거리(Lv2+ +25%, 1회성), 반각(Lv1-4=60°, Lv5+=90°, 4단계에서 확장
  레벨을 doc대로 Lv4→Lv5로 정정)의 부채꼴 판정을 0.2초 간격으로 실행, 타격된 적을 플레이어 반대 방향으로
  밀어냄.
- **[4단계 추가]** Lv3+: 넉백 속도 +40%. Lv4+: 부채꼴 안의 적에게 `SetDamageAmpMultiplier(1.15f)` 피해
  증폭 디버프(범위 이탈/홀드 릴리즈 시 자동 해제).

### 글록켄슈필 (Glockenspiel)
- **기획서**: 체력 최고 적 머리 위 별빛 낙하. 4/8마디 버스트 성공 시 별빛 폭포.
- **구현**: `ExecuteGlockenspiel()`. 스플래시 반경 0.6(Lv3+ +0.5). 전역 콤보가 4의 배수(Lv4+)일 때 별
  추가 낙하 2개(랜덤 오프셋) — 4단계에서 "8배수면 2개/아니면 1개" 조건 분기를 doc대로 "항상 +2"로
  단순화·정정.
- **[4단계 추가]** Lv2+: 데미지 +30%. Lv5: 주 타겟과 다른 가장 가까운 적을 향해 `HomingShrapnelProjectile`
  유도 파편 발사, 명중 시 피해 + 0.5초 기절(다른 적이 없으면 스킵).

### 첼로 (Cello)
- **기획서**: 13칸 베이스 롱노트. 홀드 중 가장 가까운 적 발밑에 고정 중력장, 이속 감소 + 지속 타격.
- **구현**: `CelloGravityFieldEffect`. 홀드 시작 시점의 최근접 적 위치에 필드를 고정(적을 따라가지
  않음 — 기획서의 "고정된" 의도 그대로). 반경(Lv2+ +20%, 1회성), 감속(Lv1 40%/Lv3+ 60% — 4단계에서
  시작값 50%→40%로 정정), 0.4초 간격 지속 타격. 범위를 벗어난 적은 감속 해제.
- **[4단계 추가]** Lv4+: 홀드를 릴리즈해도 필드가 즉시 사라지지 않고 약 1.3초간 잔류(`isLingering`
  플래그 + 자체 `Update()`로 코디네이터 없이 계속 틱). Lv5: 범위 내 적을 중앙으로 지속적으로 끌어당김.

### 팀파니 (Timpani)
- **기획서**: 강세 단타 시 "팀파니 캐논"(즉발 충격파), 16마디 롤ing 홀드 시 "지진 융단폭격"(연속 포격).
  두 메커니즘이 서로 다른 노트 특성(단타 vs 홀드)으로 각각 설명되어 있음.
- **구현**: `TimpaniBombardmentEffect`. 0단계 홀드 인프라가 악기당 1가지 입력 모드만 지원하므로,
  "홀드 시작 = 즉발 캐논, 홀드 유지 = 융단폭격"으로 두 메커니즘을 하나의 홀드 흐름에 합쳤음(3번 항목
  참고). 즉발 캐논 반경(Lv2+ +25%), 융단폭격 빈도(Lv3+ +50%)·데미지 절반 — 4단계에서 두 수치의 적용
  레벨을 doc대로 Lv3→Lv2, Lv4→Lv3으로 각각 한 단계씩 앞당겨 정정.
- **[4단계 추가]** Lv4+: 착탄한 적에게 1초 기절. Lv5: 착탄 지점에 `LingeringZoneEffect`(지진 지대)가
  생성되어 3초간 지속 타격.

### 마림바 (Marimba)
- **기획서**: 3, 11번 엇박자 단타. 이동 방향 일직선 관통 파동. 엇박 성공 시(Lv3) 파동 크기 +30%.
- **구현**: `ExecuteMarimba()`. 이동 방향 기준 관통 파동(관통 Lv1=3, Lv2+=5), Lv4+ 화면 끝 1회 바운스.
- **[4단계 추가 — 버그 수정]** Lv3+: `sizeMultiplier = 1.3f` 분기를 새로 추가해 파동의 시각적 크기와
  히트 반경이 실제로 +30%가 되도록 수정(이전엔 Lv3에 해당하는 코드 분기가 아예 없어 완전한 공백
  레벨이었습니다 — 3번 섹션 4항 참고). Lv5: 피격한 적에게 이동속도 30% 감소(1초) + 밀쳐냄을 동시에 적용.

### 벨 (Bell)
- **기획서**: 5, 13번 엇박자 단타. 가장 가까운 적 중심 8방향 성광.
- **구현**: `ExecuteBell()`. 사거리(Lv2+ +30%, 1회성 — 4단계에서 "레벨마다 복리로 증가"하던 걸 doc대로
  1회성 적용으로 정정), 관통 Lv1-2=3/Lv3+=5, Lv4+ 8방향 발사 2연속(더블 버스트).
- **[4단계 추가]** Lv5: 성광의 중심점에 `LingeringZoneEffect`("잔향") 장판이 생성되어 1.5초간 지속 타격.

## 3. 메커니즘 doc과 달라진 점

전체 10종에 공통으로 적용된 단순화/변경 사항입니다. 각 악기 섹션에서 개별적으로 언급된 내용과 중복될
수 있습니다.

1. **레벨별 수치는 전부 임의값**: 메커니즘 doc은 각 악기의 메커니즘을 정성적으로만 설명하고(예: "관통력
   강화", "범위 증가"), 구체적인 수치를 제시하지 않습니다. 위에 정리된 모든 반경/관통/발사 수/간격
   수치는 개발 과정에서 감으로 정한 값입니다 — 그런데 실제로는 밸런스 doc 5번 항목에 악기별 구체적인
   Lv1~5 성장표가 이미 정의되어 있었고, 이번 구현은 그것을 참고하지 않았습니다. 자세한 차이는 4번
   섹션 참고.
2. **전역 콤보 카운터 (악기별 콤보 아님)**: 피아노의 "6연타 캐스케이드", 글록켄슈필의 "4/8버스트"는
   기획서상 해당 악기 자신의 연속 히트를 의미하는 것으로 보이지만, 구현은 모든 레인을 통틀은 전역
   콤보(`RhythmManager.CurrentCombo`)를 그대로 재사용합니다. 즉 다른 악기로 쌓은 콤보가 피아노/글록켄슈필의
   버스트를 트리거할 수 있습니다.
3. **팀파니의 두 메커니즘 통합**: 메커니즘 doc은 "단타 캐논"과 "홀드 롤ing 폭격"을 서로 다른 노트
   특성으로 설명하지만, 0단계 홀드 인프라는 악기당 1가지 입력 모드(전부 홀드)만 지원합니다. "홀드
   시작=즉발 캐논, 유지=융단폭격"으로 합쳐서 구현했습니다.
4. **오프비트(엇박) 구분 없음**: 마림바(3,11번 엇박)와 벨(5,13번 엇박)은 기획서상 특정 스텝에서만
   발동해야 하는 뉘앙스가 있지만, 실제로는 노트 패턴 자체가 이미 해당 스텝에 배치되어 있을 뿐 "엇박
   타이밍에 맞았는가"를 별도로 판정하지는 않습니다. **(마림바 Lv3 버그는 4단계에서 수정 완료)** 이전
   버전의 이 문서는 마림바 Lv3의 "파동 크기 +30%"가 "구분 없이 항상 적용된다"고 잘못 적었었는데, 실제로는
   `ExecuteMarimba()`에 Lv3 조건 분기 자체가 없어 완전한 공백 레벨이었습니다. 4단계 작업에서
   `sizeMultiplier = (level >= 3) ? 1.3f : 1f` 분기를 추가해 실제로 적용되도록 수정했고, Unity MCP
   실측 검증에서 Lv2/Lv3 히트 반경 차이를 확인해 PASS로 확정했습니다(6번 섹션 참고).
5. **플루트 "지나간 자리" 근사**: 기획서는 "플레이어가 지나간 자리"(실제 이동 궤적)를 명시하지만, 이동
   경로를 기록하는 인프라가 없어 "바라보는 방향의 반대쪽에 고정 오프셋(0.8유닛)"으로 근사했습니다.
6. **Lv5 전용 추가 효과 — 4단계에서 반영 완료**: 벨의 "지나간 자리 잔향 지속 타격", 마림바의
   "감속+밀쳐냄", 글록켄슈필의 "2차 유도 파편+기절", 바이올린의 "검기 잔향", 프렌치호른의 "각도 확장",
   첼로의 "중앙 끌어당김", 팀파니의 "기절/지진 지대", 드럼의 "2연속 충격파", 플루트의 "바람 파편 폭발"
   등 밸런스 doc이 요구한 Lv4~5 전용 부가 효과를 4단계 작업에서 전부 새로 구현했습니다. 상세 내용은
   각 악기의 "[4단계 추가]" 항목과 4번 섹션 참고.
7. **프렌치호른 부채꼴 시각화 = 원형 근사**: 실제 피해 판정은 정확한 부채꼴(각도 계산)을 사용하지만,
   화면에 보이는 범위 표시는 단순화를 위해 반투명 원형 스프라이트로 근사했습니다.
8. **드럼 오라는 M_rhythm 미적용**: 판정 성공과 무관한 상시 효과라는 성격에 맞춰, 리듬 정확도 배율
   (M_rhythm)은 의도적으로 제외하고 시포르찬도(M_stat) 패시브만 반영했습니다. 판정 성공 시의 "비트 뱅"
   폭발딜은 다른 악기와 동일하게 M_rhythm을 포함한 표준 공식을 그대로 사용합니다.
9. **레가토(Legato) 패시브 / 악기 Lv4 "Multi+1" 스탯이 사실상 비활성 상태**: 밸런스 doc이 정의한 레가토
   패시브("투사체 수 +1(Lv3)/+2(Lv5)")와 각 악기 Lv4의 `extraProjectiles`("Multi +1")는 과거 범용
   폴백 투사체 로직에서만 소비되던 값입니다. 10종 전체가 각자 전용 디스패처로 처리되면서 이 폴백
   로직에 실질적으로 도달하지 않게 되었고, 개별 악기 디스패처(`ExecutePiano`, `ViolinOrbitEffect` 등)는
   "추가 투사체 수"라는 개념을 아예 받지 않습니다. 즉 두 스탯은 UI에는 계속 "Multi +N"으로 표시되지만
   실제 게임플레이에는 아무 영향이 없는 상태입니다. 폴백 로직 자체는 신규 악기 추가 대비 안전장치로
   코드에 남겨두었습니다(`RhythmAttackManager.HandleRhythmHit()` 하단 참고).

밸런스 doc 5번 "10종 전체 악기 5단계 레벨업 성장표 & Target DPS"에는 악기별로 Lv1~5의 구체적인 성장

### 종합 소견 (4단계 실측 검증 완료 후)
- **Target DPS 검증은 여전히 미실시**: 밸런스 doc은 각 악기 레벨마다 목표 DPS(예: 피아노

  doc이 요구하는 "효과의 종류·적용 레벨"은 실측으로 확인됐지만, 실제로 달성되는 DPS를 목표치에 맞춰
  역산하거나 정량적으로 측정하지는 않았습니다. 정식 밸런스 패스 때 반드시 확인이 필요합니다.
- **레벨 임계값 어긋남은 4단계에서 정정 완료, 실측으로 재확인됨**: 프렌치호른(각도 확장 Lv4→Lv5),
  팀파니(범위 Lv3→Lv2, 빈도 Lv4→Lv3), 벨(사거리 복리 증가→1회성 적용)이 doc 기준으로 정정됐고, 각각
  Unity MCP 실측에서 해당 레벨/수치가 정확히 일치함을 확인했습니다.
- **부가 효과(슬로우/스턴/디버프/2차 폭발) 전부 구현 및 실측 PASS**: 드럼(둔화, 오라 +50%), 첼로
  (끌어당김), 팀파니(기절, 지진 잔류), 프렌치호른(피해 증폭 디버프), 바이올린/벨/글록켄슈필/마림바
  (Lv5 전용 효과), 플루트(바람 파편)까지 doc이 요구하는 "부가 효과"성 메커니즘이 4단계에서 구현되고
  Unity MCP 실측으로 전부 확인됐습니다. 다만 감속/기절 수치 상당수는 doc에 구체적 값이 없어 임의로
  정한 값이며(테스트 가이드 4번 섹션 참고), "그 값 자체가 적정한가"는 검증 범위 밖입니다.
- **마림바 Lv3 버그는 4단계에서 수정 완료, 실측으로 확인됨**: 아무 분기도 없이 "레벨을 올려도 변화가
  없던" 상태가 고쳐졌고, Lv2/Lv3 히트 반경 차이가 실측으로 정확히 확인됐습니다.
- **여전히 남아있는 차이**: 첼로 Lv4("중력장 지속시간 +30%")는 구조적으로 doc 원문 그대로 구현이
  불가능해 "릴리즈 후 1.3초 잔류"로 재해석했고(코드/실측 모두 이 해석대로 정확히 동작 — 해석의 타당성
  자체는 설계자 확인 필요), 벨 Lv4의 "엑센트 박자" 판정은 여전히 구분 없이 항상 적용됩니다.

## 6. 검증 상태

10종 전체가 1~3단계에 걸쳐 Unity MCP 실측 검증을 통과했습니다. 발견된 유일한 치명적 버그(바이올린
`TickDamage()`의 딕셔너리 순회 중 수정 크래시)는 2단계 2차 검증에서 수정 확인되었고, 그 외에는 버그 없이
전부 PASS로 종료되었습니다. 상세 로그는 `Docs/archive/instrument_mechanics_phase1_test_result.md` /
`..._phase2_test_result.md` / `..._phase3_test_result.md`를 참고하세요.

**4단계(밸런스 doc 5번 항목 정합화)도 Unity MCP 실측 검증을 완료했습니다 — 10종 전체 및 공용 상태이상
인프라(`EnemyMonster`) 전부 PASS, 치명적 버그 없음.** 우려했던 명명 인자+위치 인자 혼용 문법도 실제
컴파일로 문제없음이 확인됐습니다(C# 7.2 "non-trailing named arguments" 규칙 — 명명 인자가 자신의 실제
선언 위치와 일치하면 그 뒤에 위치 인자가 와도 합법). 상세 로그는
`Docs/instrument_mechanics_phase4_test_result.md` 참고. 이번 라운드에서 4번 섹션 표의 "부분일치/미구현"
항목 대부분이 "일치"로 갱신됐고, 위 드럼 Lv4 오라처럼 문서 초안이 실제 코드 상태를 잘못 반영했던 항목도
실측 과정에서 바로잡았습니다.

검증 중 발견된 사소한 관찰 사항(치명적 버그 아님, 설계자 판단 권장):
- **프렌치호른 Lv4**: 피해 증폭 디버프를 처음 적용하는 바로 그 틱에서 프렌치호른 자신의 데미지도
  증폭 혜택을 받습니다(10→12 데미지). "다른 악기 피해만 증폭"이라는 명시적 요구사항은 없어 설계
  위반은 아닙니다.
- **글록켄슈필 Lv5**: 2차 유도 파편 타겟 탐색(`FindSecondaryShrapnelTarget`)과 파편 자체가 거리 제한이
  없습니다. "타겟이 없으면 스킵" 조건은 맵 전체에 다른 적이 정말 한 마리도 없을 때만 발동하므로, 일반
  플레이에서는 스킵이 거의 발생하지 않고 파편이 매우 먼 적을 향해 날아갈 수도 있습니다.
- **글록켄슈필 Lv5 명중 시 기절**: 에디터의 프레임 몰림(1~3단계에서도 반복된 환경적 한계) 때문에
  "명중 즉시 0.5초 기절"이 실측 창 안에서 이미 만료된 상태로 관측되어, 지속시간 자체의 실시간 확인은
  못 했습니다. 소스 코드상 호출(`HomingShrapnelProjectile.cs:45`)은 확인됐고 `ApplyStun` 메커니즘
  자체는 별도로 100% 검증되어, 배선은 올바른 것으로 판단합니다.

여전히 남아있는 항목(4단계 범위 밖, 이월): Target DPS 실측/튜닝, 첼로 Lv4 "잔류시간" 해석의 설계 타당성
