# 10종 악기별 공격 메커니즘 구현 정리

`10종 악기별 공격 메커니즘 기획서.docx`(메커니즘 기획서, 이하 "메커니즘 doc")와 `game_balance_design.docx`
(밸런스 기획서, 이하 "밸런스 doc") 두 문서에 걸쳐 정의된 10종 악기(드럼/피아노/바이올린/플루트/
프렌치호른/글록켄슈필/첼로/팀파니/마림바/벨)의 공격 메커니즘 구현이 3단계(1단계: 탭 4종, 2단계: 홀드
4종, 3단계: 드럼/플루트)에 걸쳐 전부 완료되었습니다. 이 문서는 두 기획서 내용과 실제 구현을 매핑하고,
기획서와 달라진 부분을 명확히 정리한 기록입니다.

**중요**: 실제 구현 작업(1~3단계)은 메커니즘 doc만 참고하며 진행되었고, 밸런스 doc 5번 항목("10종 전체
악기 5단계 레벨업 성장표 & Target DPS")에 정의된 악기별 구체적인 레벨 1~5 성장 내용은 교차 확인하지
못한 채 별도로 임의 수치를 사용했습니다. 이번에 두 문서를 함께 재검토하면서 발견된 차이점은 4번 섹션에
정리했습니다.

각 단계의 실측 검증 과정과 발견된 버그는 `archive/instrument_mechanics_phase1_test_result.md` /
`archive/..._phase2_test_result.md` / `archive/..._phase3_test_result.md`(과거 테스트 가이드/결과 모음
`Docs/archive/` 폴더로 이동됨)에 별도로 남아있습니다. 이 문서는 "최종적으로 무엇이 어떻게
구현되었는가"만 정리한 요약본입니다.

---

## 1. 전체 구조

모든 악기 공격은 판정 성공 이벤트(`RhythmManager.OnHitSuccessEvent`)를 `RhythmAttackManager.HandleRhythmHit()`가
받아서 처리합니다. 악기는 노트 입력 방식에 따라 두 그룹으로 나뉩니다.

- **탭(Tap) 기반 5종** — 피아노, 벨, 마림바, 글록켄슈필, 드럼. 판정 성공 즉시 1회성 공격이 발동합니다.
  `InstrumentAttackDispatcher.IsImplemented()` / `Execute()`가 담당합니다.
- **홀드(Hold) 기반 5종** — 바이올린, 프렌치호른, 첼로, 팀파니, 플루트. 판정 성공 시점이 홀드 "시작"이고,
  이후 키를 누르고 있는 동안 매 프레임 유지 효과가, 떼는 순간 해제 효과가 발동합니다.
  `InstrumentAttackDispatcher.IsHoldImplemented()` / `HoldEffectCoordinator`(레인별 지속 이펙트 관리)가
  담당합니다.

드럼만 예외적으로 위 두 파이프라인과 완전히 별개인 **판정과 무관한 상시 효과**(비트 오라)를 하나 더
가지고 있으며, 이는 `RhythmAttackManager.UpdateDrumAura()`가 매 프레임 독립적으로 처리합니다.

딜량 계산 자체(기본 DPS × M_rhythm × M_stat, 8종 패시브 스탯)는 밸런스 doc 1번·4번 항목을 그대로
따르고 있으며 이 부분은 이미 정확히 반영되어 있습니다(`RhythmAttackManager.HandleRhythmHit()`,
`PassiveStatManager`). 이번에 누락이 확인된 것은 밸런스 doc 5번 항목(악기별 5단계 성장표)입니다.

주요 공용 부품:
- `CombatTargetingUtility` — 가장 가까운 적 / 체력 최고 적 탐색
- `PiercingBeamProjectile` — 직선 관통 투사체(피아노/벨/마림바/바이올린 참격이 공유)
- `AreaImpactEffect` — 지연 낙하 광역 피해(글록켄슈필/팀파니가 공유)
- `IHoldAttackEffect` + `HoldEffectCoordinator` — 홀드 5종의 시작/유지/해제 생명주기 관리

## 2. 악기별 구현 내역

### 드럼 (Drums)
- **기획서**: 플레이어 중심 360°. 상시 "비트 오라"(근접 적에게 소량 지속 타격) + 정박(1,5,9,13) 타격 시
  "비트 뱅"(장판 팽창 + 전방위 넉백).
- **구현**: 두 효과 모두 그대로 구현.
  - 비트 오라: `RhythmAttackManager.UpdateDrumAura()`가 매 프레임 "드럼이 언락된 슬롯에 장착되어
    있는가"만 확인 — 판정 성공 여부와 완전히 무관. 0.5초 간격으로 반경(1.6 + 0.1×(Lv-1)) 내 적에게
    데미지 `max(1, round(1×M_stat))`을 가함(M_rhythm 미반영 — 아래 3번 참고).
  - 비트 뱅: `ExecuteDrums()`가 판정 성공 시 반경(2.0 + 0.3×(Lv-1)) 내 적에게 표준 딜량 공식 그대로
    데미지 + 넉백(0.6 + 0.1×(Lv-1))을 가하고 확장 링 이펙트를 재생.

### 피아노 (Piano)
- **기획서**: 가장 가까운 적 방향 관통 레이저. 14마디 6연타 성공 시 "건반 폭포"(3발 부채꼴 추가 발사).
- **구현**: `ExecutePiano()`. 관통 Lv1-2=2 / Lv3+=4. 발사 수 Lv1-3=1발 / Lv4+=2발. 전역 콤보가 6의
  배수일 때(Lv5) ±12° 부채꼴로 3발 추가.

### 바이올린 (Violin)
- **기획서**: 13칸 롱노트. 홀드 중 플레이어 둘레 회전 활 칼날, 릴리즈 시 이동 방향 부채꼴 참격.
- **구현**: `ViolinOrbitEffect`. 홀드 중 칼날 2개(Lv3+ 3개)가 반경(1.4+0.15×(Lv-1))에서 회전하며 같은
  적을 0.35초 쿨다운으로 지속 타격. 릴리즈 시 이동 방향 기준 3발(Lv4+ 5발, 관통 3/5, 스프레드 14°) 참격.

### 플루트 (Flute)
- **기획서**: 2~4칸 숏 홀드. 릴리즈 시 "플레이어가 지나간 자리"에 미니 소용돌이 생성, 주변 적을
  끌어당김(순수 CC, 다른 광역 공격과 연계).
- **구현**: `FluteVortexHoldEffect` + `FluteVortexEffect`. 3칸 홀드로 근사. 홀드 유지 중에는 아무 효과도
  없고(의도된 단순화), 릴리즈 시에만 소용돌이 발동. 반경(2.0+0.2×(Lv-1)), 지속시간(1.5+0.2×(Lv-1)),
  당김 세기 2.5(고정). **피해 없음** — 기획서의 "순수 CC" 의도를 그대로 반영.

### 프렌치호른 (French Horn)
- **기획서**: 6칸 스웰 롱노트. 홀드 중 이동 방향 전방 부채꼴에 지속 충격파 + 밀쳐냄(넉백).
- **구현**: `FrenchHornConeEffect`. 사거리(3.0+0.4×(Lv-1)), 반각(Lv1-3=60°, Lv4+=90°)의 부채꼴 판정을
  0.2초 간격으로 실행, 타격된 적을 플레이어 반대 방향으로 밀어냄.

### 글록켄슈필 (Glockenspiel)
- **기획서**: 체력 최고 적 머리 위 별빛 낙하. 4/8마디 버스트 성공 시 별빛 폭포.
- **구현**: `ExecuteGlockenspiel()`. 스플래시 반경 0.6(Lv3+ +0.5). 전역 콤보가 4의 배수(Lv4+)일 때 별
  추가 낙하(8의 배수면 2개, 아니면 1개, 랜덤 오프셋).

### 첼로 (Cello)
- **기획서**: 13칸 베이스 롱노트. 홀드 중 가장 가까운 적 발밑에 고정 중력장, 이속 감소 + 지속 타격.
- **구현**: `CelloGravityFieldEffect`. 홀드 시작 시점의 최근접 적 위치에 필드를 고정(적을 따라가지
  않음 — 기획서의 "고정된" 의도 그대로). 반경(1.8+0.2×(Lv-1)), 감속(최대 70%), 0.4초 간격 지속 타격.
  범위를 벗어난 적은 감속 해제.

### 팀파니 (Timpani)
- **기획서**: 강세 단타 시 "팀파니 캐논"(즉발 충격파), 16마디 롤ing 홀드 시 "지진 융단폭격"(연속 포격).
  두 메커니즘이 서로 다른 노트 특성(단타 vs 홀드)으로 각각 설명되어 있음.
- **구현**: `TimpaniBombardmentEffect`. 0단계 홀드 인프라가 악기당 1가지 입력 모드만 지원하므로,
  "홀드 시작 = 즉발 캐논, 홀드 유지 = 융단폭격"으로 두 메커니즘을 하나의 홀드 흐름에 합쳤음(3번 항목
  참고). 즉발 캐논 반경 1.0(Lv3+ +0.4), 융단폭격 간격 0.65초(Lv4+ 0.45초)·데미지 절반.

### 마림바 (Marimba)
- **기획서**: 3, 11번 엇박자 단타. 이동 방향 일직선 관통 파동. 엇박 성공 시(Lv3) 파동 크기 +30%.
- **구현**: `ExecuteMarimba()`. 이동 방향 기준 관통 파동(관통 Lv1=3, Lv2+=5), Lv4+ 화면 끝 1회 바운스.
  **Lv3에 해당하는 코드 분기가 아예 없음** — 관통은 Lv2에서, 바운스는 Lv4에서 이미 결정되고 그 사이
  Lv3은 실질적으로 아무 효과도 주지 않는 완전한 공백 레벨입니다(4번 섹션에서 정정).

### 벨 (Bell)
- **기획서**: 5, 13번 엇박자 단타. 가장 가까운 적 중심 8방향 성광.
- **구현**: `ExecuteBell()`. 사거리 2.5×(1+0.3×(Lv-1)), 관통 Lv1-2=3/Lv3+=5, Lv4+ 8방향 발사 2연속(더블
  버스트).

## 3. 메커니즘 doc과 달라진 점

전체 10종에 공통으로 적용된 단순화/변경 사항입니다. 각 악기 섹션에서 개별적으로 언급된 내용과 중복될
수 있습니다.

1. **레벨별 수치는 전부 임의값**: 메커니즘 doc은 각 악기의 메커니즘을 정성적으로만 설명하고(예: "관통력
   강화", "범위 증가"), 구체적인 수치를 제시하지 않습니다. 위에 정리된 모든 반경/관통/발사 수/간격
   수치는 개발 과정에서 감으로 정한 값입니다 — 그런데 실제로는 밸런스 doc 5번 항목에 악기별 구체적인
   Lv1~5 성장표가 이미 정의되어 있었고, 이번 구현은 그것을 참고하지 않았습니다. 자세한 차이는 4번
   섹션 참고.
2. **전역 콤보 카운터 (악기별 콤보 아님)**: 피아노의 "6연타 캐스케이드", 글록켄슈필의 "4/8버스트"는
   기획서상 해당 악기 자신의 연속 히트를 의미하는 것으로 보이지만, 구현은 모든 레인을 통틀은 전역
   콤보(`RhythmManager.CurrentCombo`)를 그대로 재사용합니다. 즉 다른 악기로 쌓은 콤보가 피아노/글록켄슈필의
   버스트를 트리거할 수 있습니다.
3. **팀파니의 두 메커니즘 통합**: 메커니즘 doc은 "단타 캐논"과 "홀드 롤ing 폭격"을 서로 다른 노트
   특성으로 설명하지만, 0단계 홀드 인프라는 악기당 1가지 입력 모드(전부 홀드)만 지원합니다. "홀드
   시작=즉발 캐논, 유지=융단폭격"으로 합쳐서 구현했습니다.
4. **오프비트(엇박) 구분 없음 + 마림바 Lv3 공백(정정)**: 마림바(3,11번 엇박)와 벨(5,13번 엇박)은
   기획서상 특정 스텝에서만 발동해야 하는 뉘앙스가 있지만, 실제로는 노트 패턴 자체가 이미 해당 스텝에
   배치되어 있을 뿐 "엇박 타이밍에 맞았는가"를 별도로 판정하지는 않습니다. **(정정)** 이전 버전의 이
   문서는 마림바 Lv3의 "파동 크기 +30%"가 "구분 없이 항상 적용된다"고 적었는데, 실제 코드를 다시 확인한
   결과 이는 부정확한 서술이었습니다 — `ExecuteMarimba()`에는 Lv3을 조건으로 하는 분기 자체가 없어서,
   크기 증가든 뭐든 어떤 형태로도 전혀 적용되지 않습니다. 관통(Lv2)과 바운스(Lv4) 사이에서 Lv3은 순수한
   공백 레벨입니다. 이건 "단순화"가 아니라 구현 누락(버그)에 가까우므로 다음 작업 때 수정이 필요합니다.
5. **플루트 "지나간 자리" 근사**: 기획서는 "플레이어가 지나간 자리"(실제 이동 궤적)를 명시하지만, 이동
   경로를 기록하는 인프라가 없어 "바라보는 방향의 반대쪽에 고정 오프셋(0.8유닛)"으로 근사했습니다.
6. **Lv5 전용 추가 효과 미구현**: 벨의 "지나간 자리 잔향 지속 타격", 마림바의 "감속+밀쳐냄", 글록켄슈필의
   "2차 유도 파편+기절"은 메커니즘 doc에 Lv5 전용으로 명시되어 있지만 구현하지 않았습니다. 4종 모두
   Lv5는 Lv4와 동일하게 동작합니다. (밸런스 doc에도 각 악기 Lv5마다 고유 효과가 정의되어 있으며, 이
   역시 대부분 미구현입니다 — 4번 섹션 참고.)
7. **프렌치호른 부채꼴 시각화 = 원형 근사**: 실제 피해 판정은 정확한 부채꼴(각도 계산)을 사용하지만,
   화면에 보이는 범위 표시는 단순화를 위해 반투명 원형 스프라이트로 근사했습니다.
8. **드럼 오라는 M_rhythm 미적용**: 판정 성공과 무관한 상시 효과라는 성격에 맞춰, 리듬 정확도 배율
   (M_rhythm)은 의도적으로 제외하고 시포르찬도(M_stat) 패시브만 반영했습니다. 판정 성공 시의 "비트 뱅"
   폭발딜은 다른 악기와 동일하게 M_rhythm을 포함한 표준 공식을 그대로 사용합니다.
9. **레가토(Legato) 패시브 / 악기 Lv4 "Multi+1" 스탯이 사실상 비활성 상태**: 밸런스 doc이 정의한 레가토
   패시브("투사체 수 +1(Lv3)/+2(Lv5)")와 각 악기 Lv4의 `extraProjectiles`("Multi +1")는 과거 범용
   폴백 투사체 로직에서만 소비되던 값입니다. 10종 전체가 각자 전용 디스패처로 처리되면서 이 폴백
   로직에 실질적으로 도달하지 않게 되었고, 개별 악기 디스패처(`ExecutePiano`, `ViolinOrbitEffect` 등)는
   "추가 투사체 수"라는 개념을 아예 받지 않습니다. 즉 두 스탯은 UI에는 계속 "Multi +N"으로 표시되지만
   실제 게임플레이에는 아무 영향이 없는 상태입니다. 폴백 로직 자체는 신규 악기 추가 대비 안전장치로
   코드에 남겨두었습니다(`RhythmAttackManager.HandleRhythmHit()` 하단 참고).

### 종합 소견
- **Target DPS 검증 미실시**: 밸런스 doc은 각 악기 레벨마다 목표 DPS(예: 피아노 30→45→70→100→150)를
  명시하고 이를 근거로 "10분 시점 총합 750 DPS" 밸런스를 설계했습니다. 이번 구현에서는 이 목표 DPS에
  맞춰 수치를 역산하지 않았고, 실제로 달성되는 DPS를 측정/검증하지도 않았습니다. 정식 밸런스 패스 때
  반드시 확인이 필요합니다.
- **레벨 임계값이 대체로 한 단계씩 밀려 있음**: 프렌치호른(각도 확장 Lv5→Lv4), 팀파니(범위 Lv2→Lv3,
  빈도 Lv3→Lv4)처럼, 방향은 맞지만 "몇 레벨에 어떤 효과가 터지는가"가 doc과 어긋나는 경우가 여러 건
  있습니다.
- **부가 효과(슬로우/스턴/디버프/2차 폭발) 대부분 미구현**: 드럼(둔화), 첼로(끌어당김), 팀파니(기절,
  지진 잔류), 프렌치호른(피해 증폭 디버프), 바이올린/벨/글록켄슈필/마림바(Lv5 전용 효과)까지, doc이
  요구하는 "부가 효과"성 메커니즘은 거의 전부 아직 없습니다. 현재 구현은 doc이 그리는 "레벨이 오를수록
  질적으로 달라지는 무기"보다는 "수치만 완만히 강해지는 무기"에 가깝습니다.
- **마림바 Lv3만은 단순화가 아니라 버그**: 다른 항목들은 "다르게 구현했다"고 볼 수 있지만, 마림바 Lv3은
  아무 분기도 없어 "레벨을 올려도 아무 변화가 없는" 상태이므로 우선순위 높은 수정 대상입니다.

## 6. 검증 상태

10종 전체가 1~3단계에 걸쳐 Unity MCP 실측 검증을 통과했습니다. 발견된 유일한 치명적 버그(바이올린
`TickDamage()`의 딕셔너리 순회 중 수정 크래시)는 2단계 2차 검증에서 수정 확인되었고, 그 외에는 버그 없이
전부 PASS로 종료되었습니다. 상세 로그는 `Docs/archive/instrument_mechanics_phase1_test_result.md` /
`..._phase2_test_result.md` / `..._phase3_test_result.md`를 참고하세요.

다만 이 검증은 "코드가 의도한 대로 동작하는가"만 확인한 것이고, "밸런스 doc이 요구한 수치·Target DPS와
일치하는가"는 검증 범위에 포함되지 않았습니다 — 4번 섹션에 정리된 차이점은 이번 재검토에서 새로 발견된
것으로, 아직 어떤 실측 라운드에서도 다뤄지지 않았습니다.
