# 10종 악기별 공격 메커니즘 - 3단계(드럼/플루트) 검증 결과

`instrument_mechanics_phase3_test_guide.md`에 정리된 절차에 따라 **Unity MCP(Unity 6000.5.5f1,
`My project` 인스턴스)**로 실측 검증을 진행한 결과입니다. 1·2단계에서 정립한 방법론
(`Time.timeScale=0` + 리플렉션으로 private 필드/메서드 직접 제어)을 기본으로 사용하되, 드럼 오라처럼
`Time.deltaTime`을 파라미터가 아니라 메서드 내부에서 직접 읽는 로직은 결정론적 재현이 불가능해 별도로
대응했습니다 (아래 "테스트 방법론" 참고).

**종합 결과: 드럼(상시 오라 + 비트 뱅)과 플루트(릴리즈 소용돌이) 전부 PASS. 발견된 버그 없음. 이번
라운드로 10종 악기 구현이 전부 완료되었습니다.**

## 0. 사전 준비

- `refresh_unity(mode=force, compile=request)` → 컴파일 에러 없음. 콘솔에 남은 항목은 MCP 플러그인
  자체의 WebSocket 경고 1건뿐(프로젝트 코드와 무관).
- Play Mode 진입 직후 드럼이 자동 장착되어 `DrumBeatAura` GameObject가 즉시 활성 상태로 존재함을 확인 —
  가이드 3번 항목("오라가 안 보이면 그 자체가 버그")의 반대 케이스(정상)를 확인.

→ **PASS**

### 테스트 방법론: 드럼 오라 같은 "메서드 내부에서 Time.deltaTime을 직접 읽는" 로직 대응

2단계 홀드 이펙트들(`OnHoldTick(float deltaTime)`)은 델타타임을 파라미터로 받아서 리플렉션으로 원하는
값을 직접 넣어 결정론적으로 재현할 수 있었습니다. 하지만 `RhythmAttackManager.UpdateDrumAura()`와
`FluteVortexEffect.Update()`는 `Time.deltaTime`을 메서드 **내부에서 직접** 읽기 때문에, `Time.timeScale=0`
상태에서는 아무리 메서드를 반복 호출해도 항상 `deltaTime=0`이라 이동/누적 로직을 검증할 수 없습니다.

- **드럼 오라의 틱 누적(`drumAuraTickTimer`)**: 이 필드는 `deltaTime`과 무관하게 직접 리플렉션으로
  원하는 값을 주입할 수 있어서 문제없이 결정론적으로 재현했습니다.
- **플루트 소용돌이의 "당김" 이동량**: `FluteVortexEffect.Update()`가 매 프레임 `Time.deltaTime`만큼
  위치를 이동시키는 구조라 이 방법이 통하지 않았습니다. 처음 시도한 "아주 짧게 `Time.timeScale=1f`로
  풀었다가 즉시 확인" 방식은, 1단계에서 발견했던 것과 동일한 "에디터가 백그라운드에서 프레임을 몰아서
  처리하는" 특성 때문에 도구 호출 사이의 아주 짧은 실제 대기(심지어 `sleep` 없이도)만으로 소용돌이의
  지속시간(1.5초)이 통째로 지나가 버리는 문제가 반복 발생했습니다. 게다가 이전 테스트에서 켜뒀던 드럼
  오라가 백그라운드에서 계속 돌면서 데미지를 주는 바람에 "소용돌이는 무피해"를 확인하려던 실험이 한 번
  오염되기도 했습니다(더미가 hp 100000→99962로 줄어든 원인을 추적한 결과, 드럼 오라의 누적 틱임을
  확인 — 소용돌이 자체의 버그 아님).
  - **최종 해결책**: 드럼 오라를 테스트 동안만 임시로 꺼두고, 더미 몹의 `playerTransform`을 `null`로
    초기화해 몹 자신의 추적 이동 로직까지 차단한 뒤, 실시간을 아주 짧게 허용하는 방식으로 "소용돌이의
    당김 효과만" 깨끗하게 분리해 검증했습니다 (상세 결과는 아래 2번 섹션 참고).

## 1. 드럼 — 상시 오라 — PASS

- **자동 장착 확인**: Play Mode 진입 즉시 `DrumBeatAura` GameObject가 존재하고 활성 상태임을 확인.
- **위치 추적**: 플레이어를 임의 위치로 이동시키면 오라도 즉시 같은 위치로 따라감을 확인.
- **틱 간격(0.5초) 게이팅**: 누적 0.4초에서는 데미지 없음, 누적 0.5초 시점에 정확히 발동하고 타이머가
  0으로 리셋됨을 확인.
- **범위 내/외 판정**: 오라 범위(Lv1 기준 1.6) 안의 적만 데미지를 받고, 범위 밖의 적은 전혀 영향받지 않음.
- **레벨별 범위 증가**: 드럼을 Lv4까지 올린 뒤(`radius=1.6+0.1×3=1.9`), Lv1 범위(1.6)로는 닿지 않는
  거리 1.75의 적이 Lv4에서는 정확히 맞음을 확인.
- **M_rhythm 미적용, M_stat만 반영**: 리듬 성공률을 100%(`M_rhythm=2.0`)로 고정해도 오라 데미지는 그대로
  1이었고(=M_rhythm 미반영), 시포르찬도 패시브를 Lv5(`M_stat=1.5`)까지 올리자 오라 데미지가
  `Max(1,Round(1×1.5))=2`로 정확히 변함을 확인 — 가이드에 명시된 설계 의도와 정확히 일치.
- **`IsDrumsActive()` 로직 (드럼이 비활성 슬롯으로 밀려나는 가상 시나리오)**: `InstrumentManager`의
  장착 리스트를 리플렉션으로 비운 상태에서 `IsDrumsActive()`가 정확히 `False`를 반환하고, 이 시점에
  `UpdateDrumAura()`를 호출하면 오라 비주얼이 실제로 `SetActive(false)`됨을 확인. 리스트를 복구하면
  다시 `True`로 전환되고 오라도 재활성화됨을 확인. (처음 시도에서 `GameObject.Find()`로 재조회하다가
  "비활성 오브젝트는 `Find`로 못 찾는" Unity 특성 때문에 오탐이 있었으나, 오브젝트 참조를 미리 캐싱해
  재확인해 해결 — 테스트 스크립트 실수였고 게임 로직 버그 아님)

## 2. 드럼 — 비트 뱅 — PASS

- **정박 판정 시 넉백 파동**: `InstrumentAttackDispatcher.Execute(Drums, ...)` 직접 호출로 재현. 범위 내
  적은 데미지 + 플레이어 반대 방향으로 밀려남(넉백)을 확인, 범위 밖 적은 무영향.
- **오라보다 넓은 범위**: Lv1 기준 오라(1.6) vs 비트 뱅(2.0), Lv4 기준 오라(1.9) vs 비트 뱅(2.9) — 모든
  레벨에서 비트 뱅이 오라보다 명확히 넓음을 `ShockwaveVisualEffect`의 실제 스케일 값으로 확인.
- **레벨 스케일링**: 비트 뱅 반경이 `2.0 + 0.3×(level-1)` 공식 그대로 정확히 계산됨을 확인.

## 3. 플루트 — PASS

- **홀드 유지 중 무효과**: 홀드 시작 시 `HoldEffect_Flute`에 자식 이펙트가 전혀 없고, `OnHoldTick`을
  호출해도(0.5초어치) `FluteVortex`가 생성되지 않음을 확인 — "유지 중 효과 없음"이 의도대로 정확히
  구현됨.
- **릴리즈 시 소용돌이 생성 위치**: 플레이어가 바라보는 방향(Right)의 반대쪽으로 정확히 0.8유닛 떨어진
  위치(`(-0.8, 0, 0)`)에 생성됨을 확인.
- **당김 효과 (무피해 CC)**: 드럼 오라를 테스트 동안 끄고, 몹 자체의 추적 이동도 차단한 순수 조건에서
  재검증한 결과, 거리 1.5 지점에 있던 몹이 소용돌이 중심까지 끌려와 최종적으로 거리 0.05까지 근접했고,
  이 과정에서 hp는 처음(100000)과 끝(100000)이 정확히 동일해 **피해가 전혀 없음**을 확인 — 기획서의
  "순수 CC" 의도와 정확히 일치.
- **지속시간 만료 후 자동 소멸**: `elapsed`를 `duration` 이상으로 강제 설정한 뒤 `Update()`를 직접
  호출하면 `Destroy(gameObject)`가 호출됨을 확인 (다른 라운드에서도 확인된 Unity의 지연 파괴 특성상
  그 프레임엔 참조가 남아있을 수 있으나, 이후 조회에서 실제로 사라짐을 확인).
- **레벨 스케일링**: Lv1 `radius=2.0, duration=1.5` / Lv4 `radius=2.6, duration=2.1` 모두 공식
  (`radius=2.0+0.2×(level-1)`, `duration=1.5+0.2×(level-1)`) 그대로 정확.

## 4. 가이드에 명시된 알려진 단순화 사항 — 코드로 재확인

- **드럼 오라 데미지 산식(M_rhythm 제외)**: 위 1번 섹션에서 실측으로 정확히 확인됨 — 설계 의도대로 구현됨.
- **드럼 슬롯 고정 가정**: `InstrumentManager`에 장착 해제 API가 없음을 코드로 재확인. `IsDrumsActive()`는
  실제로 리스트를 직접 조작했을 때만 `False`를 반환했으며, 정상적인 게임 플로우(UI를 통한 장착/해제)로는
  드럼을 뗄 방법이 없어 사실상 항상 `True`를 반환하는 방어적 코드라는 가이드의 추측과 일치.
- **플루트 "지나간 자리" 근사**: 코드에 이동 궤적을 기록하는 인프라가 전혀 없고, `GetFacingDirectionVector()`
  기반 고정 오프셋(0.8유닛)만 사용함을 확인. 가이드 설명과 일치.
- **플루트 완주 여부 무관 발동**: `OnHoldReleased(bool completedFully)`에서 `completedFully` 파라미터를
  전혀 사용하지 않고 무조건 소용돌이를 생성함을 코드로 확인. 가이드 설명과 일치.
- **Lv5 전용 효과 스텁**: 드럼/플루트 모두 레벨 조건이 전부 `Mathf.Max(0, level-1)` 선형식이라 Lv5 전용
  분기가 없음을 확인. 가이드 설명대로 미구현 상태.
